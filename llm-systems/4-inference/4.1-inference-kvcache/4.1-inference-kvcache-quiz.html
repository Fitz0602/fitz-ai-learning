T1-4.1-①-a · 概念辨析
LLM 推理的 Prefill 和 Decode 阶段，分别受限于什么资源？
A. Prefill 受内存带宽限制，Decode 受算力限制
B. Prefill 受算力限制，Decode 受内存带宽限制
C. 两者都受算力限制
D. 两者都受内存带宽限制
✅ 正确答案 B。Prefill 阶段一次性并行处理全部 prompt tokens，大量矩阵乘法使得 GPU 算力单元繁忙（Compute-bound，MFU ~60%）；Decode 阶段每步只生成 1 个 token，GPU 95% 时间在等内存搬运（Memory-bound，MFU ~5-10%）。→ 回到 §①
T1-4.1-①-b · 判断应用
某 API 定价中，输入 token 价格 $1/M，输出 token 价格 $10/M。输出比输入贵 10 倍，最根本的原因是什么？
A. 输出 token 的模型参数更多
B. 输出阶段需要逐 token 串行生成，GPU 算力利用率极低
C. 输出 token 需要更多的训练数据
D. 输出 token 的 KV Cache 更大
✅ 正确答案 B。Decode 阶段每个 token 都需要一次完整的前向传播（读模型权重 + KV Cache），但只产出 1 个 token，GPU MFU 仅 5-10%。Prefill 阶段一次处理多个 token 均摊了权重读取成本。→ 回到 §①
T1-4.1-②-a · 概念辨析
KV Cache 将每步注意力计算复杂度从 $O(t^2)$ 降为 $O(t)$，这个"降维"的本质是什么？
A. 减少了注意力头的数量
B. 缓存了历史 token 的 K/V，避免每步重新计算
C. 降低了每个 token 的向量维度
D. 跳过了部分 token 的注意力计算
✅ 正确答案 B。没有 KV Cache 时，第 t 步需要重新计算所有 1~t 个 token 的 K/V 矩阵（$O(t^2)$）；有 KV Cache 后，只需计算新 token 的 $K_t, V_t$，历史 $K_{1:t-1}, V_{1:t-1}$ 直接从缓存读取，计算量降为 $O(t)$。→ 回到 §②
T1-4.1-②-b · 判断应用
一个 70B 参数模型（80层，GQA 8个KV头，d_k=128）在 FP16 下处理 128K 上下文，KV Cache 约占多少显存？
A. 约 4 GB
B. 约 40 GB
C. 约 140 GB
D. 约 800 GB
✅ 正确答案 B。计算：2 × 80(层) × 131072(128K) × 8(KV头) × 128(维度) × 2(FP16字节) = 2 × 80 × 131072 × 8 × 128 × 2 = 2 × 80 × 131072 × 2048 ≈ 2 × 80 × 268M ≈ 42.9 GB。→ 回到 §②
T1-4.1-③-a · 概念辨析
传统连续内存分配方案下，KV Cache 有效利用率仅 20-38%，最核心的浪费来源是什么？
A. GPU 算力不足导致缓存未命中
B. 为每个请求预分配最大长度的连续空间，实际输出远短于预分配
C. 注意力机制本身的计算冗余
D. 模型权重复制导致显存不足
✅ 正确答案 B。传统方案为每个请求预分配最大可能长度的连续 KV Cache，但实际输出往往短得多。加上不同请求长度差异导致的外部碎片，以及为未来 token 预留的空间，综合利用率仅 20-38%（vLLM SOSP 2023 论文数据）。→ 回到 §③
T1-4.1-③-b · 判断应用
Decode 阶段，GPU MFU 只有 5-10%。如果我们将 GPU 换成算力翻倍但内存带宽不变的新卡，Decode 速度会怎样？
A. 速度翻倍
B. 速度几乎不变
C. 速度下降
D. 速度提升 50%
✅ 正确答案 B。Decode 是 Memory-bound，瓶颈在内存带宽而非算力。延迟 ≈ (权重大小 + KV Cache 大小) / 内存带宽。算力翻倍但带宽不变，瓶颈没变，速度几乎不变。这就是"Memory Wall"的含义。→ 回到 §③
T1-4.1-④-a · 概念辨析
PagedAttention 借鉴了操作系统的哪个经典机制？它解决了什么核心问题？
A. 虚拟内存分页 → 解决 KV Cache 内存碎片和预分配浪费
B. 中断机制 → 解决 Decode 阶段延迟过高
C. 文件系统 → 解决 KV Cache 持久化存储
D. 进程调度 → 解决多请求并发排序
✅ 正确答案 A。PagedAttention 将 KV Cache 划分为固定大小的 Block，每个请求维护 Block Table（类比页表），逻辑块到物理块无需连续。内存浪费仅限最后一个 Block 未满部分（<4%），利用率从 20-38% 提升至 95%+。→ 回到 §④
T1-4.1-④-b · 判断应用
你的团队部署了一个 Agent 服务，5 个并发 Agent 共享相同的 System Prompt（2000 token）。用 SGLang 的 RadixAttention 比 vLLM 的块级哈希前缀缓存更优，根本原因是什么？
A. SGLang 的推理速度更快
B. RadixAttention 用基数树维护 LRU 缓存，跨多次生成调用自动复用 KV Block
C. vLLM 不支持前缀缓存
D. SGLang 使用更小的 Block 大小
✅ 正确答案 B。vLLM 在 Block 级别做基于哈希的前缀匹配，简洁但在复杂多调用场景（Agent、思维树）中缓存命中率较低。SGLang 的 RadixAttention 用基数树结构维护 KV Block 的 LRU 缓存，支持跨多次生成调用的自动复用，在 Agent 场景中命中率更高。→ 回到 §④
T1-4.1-⑤-a · 概念辨析
PD 分离架构（Prefill/Decode 分离）能带来 30-50% 吞吐提升，其核心物理原理是什么？
A. Prefill 和 Decode 的资源瓶颈不同，分离后各自用最合适的硬件
B. 分离后网络带宽翻倍
C. 分离后模型权重减半
D. 分离后 KV Cache 不再需要
✅ 正确答案 A。Prefill 受算力约束，Decode 受内存带宽约束。混合部署时两者互相干扰：Prefill 抢占 Decode 的计算资源，Decode 占用 Prefill 的内存带宽。分离后，Prefill 用算力强的 GPU（H100/B200），Decode 用带宽大的 GPU（MI300X），各自最优化。→ 回到 §⑤
T1-4.1-⑤-b · 判断应用
DDAgent 处理跨境汇款投诉时，每轮对话累积上下文，KV Cache 持续增长。以下哪个优化对降低 DDAgent 推理成本最直接有效？
A. 增大模型参数量
B. 启用前缀缓存（System Prompt 的 KV 跨请求复用）
C. 减少训练数据量
D. 增大 Batch Size 而不优化 KV 管理
✅ 正确答案 B。Agent 场景的核心特征是"长上下文+短追加+高前缀复用"（DualPath 论文：KV 命中率 >95%）。System Prompt 的 KV Cache 跨请求复用可以避免重复计算，直接降低 Prefill 开销。增大 Batch Size 而不优化 KV 管理只会更快地打满显存。→ 回到 §⑤
