GPU 显存与 Agent 成本模型

D5-d1 · 从显存分配到月度账单：每个 PM 都该懂的 Agent 经济学

关联章节：T1 4.1（KV Cache）+ T1 4.2（量化+Serving）

1 Agent GPU 成本的完整公式

管理 Fitz 的六个 Agent，你需要回答的最实际问题是："跑这套 Agent 系统，每月要花多少钱？"

$$C_{monthly} = \underbrace{N_{gpu} \times C_{gpu/hr} \times 720}_{\text{固定成本}} = \underbrace{\frac{QPS \times T_{avg}}{U_{util} \times C_{batch}}} _{\text{所需GPU数}} \times C_{gpu/hr} \times 720$$
变量含义典型值你的杠杆
$QPS$每秒平均请求数FXAgent ≈ 0.003 (250/天)业务增长驱动
$T_{avg}$单请求平均服务时间(s)1-30s (取决于输出长度)量化 + SpecDecode ↓
$U_{util}$GPU 利用率vLLM: 80-90%
Naive: 30-50%		引擎选型 ↑↑
$C_{batch}$每张 GPU 并发容量H100+70B FP16: ~16
H100+70B INT4: ~64		量化 ↑↑↑
$C_{gpu/hr}$GPU 单价(¥/hr)H100: ~¥22
A100: ~¥12
L4/4090: ~¥3-5		硬件选型 / 云厂商比价
直觉：想象你在开一家餐厅。$QPS$ 是客流，$T_{avg}$ 是每桌用餐时间，$U_{util}$ 是厨师利用率（不能让厨师等菜），$C_{batch}$ 是餐桌数（同样面积的餐厅，桌子摆得越密能接待越多客人），$C_{gpu/hr}$ 是租金。你的目标是：在保证服务质量的前提下最大化翻台率。

2 一张 H100 的显存去哪了？

以 Llama-3-70B 为例，部署一个推理服务的完整显存账单：

短 prompt (2K tokens): 权重占 97% 显存 → 量化的 ROI 极高 中等 prompt (16K): 权重占 80%，KV 占 17% → 两者都要优化 长 prompt (64K+): KV Cache 可能超过权重！→ DDAgent 场景核心痛点
PV (Product Value) 公式：从 3 张 H100 降到 1 张 = 月成本降 ~67%（从 ¥47 万/月降到 ~¥16 万/月，按 H100 ¥22/hr 计算）。这还只是硬件——运维、网络、故障恢复的复杂度也同步下降。

隐藏成本提醒：以上只算了 GPU 租金。实际运营还需考虑：① 网络 EIP 带宽费（API 出网流量）；② 存储（模型权重 + 日志）；③ 监控告警（Prometheus/Grafana）；④ On-call人力成本；⑤ 多可用区容灾备份。通常这些额外开销是 GPU 费的 1.5-3×。

4 成本优化的五大杠杆（按 ROI 排序）

杠杆 ① 量化：免费的午餐（大部分时候）

  • AWQ INT4：70B 模型从 140GB → 35GB，质量退化 <3%
  • FP8（Hopper 卡）：近乎无损（<0.3% PPL 退化），速度 +33%
  • 实施成本：几分钟到几十分钟（PTQ），不需要重新训练
  • Risk：数值精度敏感任务（汇率精确计算、财务报表生成）需要回归验证

杠杆 ② 引擎选型：选错引擎 = 浪费 50%+ 预算

  • naive serving → vLLM：throughput 可提升 3-23×
  • vLLM → SGLang（共享前缀场景）：再 +10-20%
  • 实施成本：半天到一天迁移（OpenAI 兼容 API 变动小）

杠杆 ⑤ 硬件降级：最后手段

  • H100 (¥22/hr) → A100 (¥12/hr)：成本 -45%，性能 -40-50%
  • A100 → L4 (¥5/hr) 或 RTX 4090 (¥3-5/hr)：成本再 -60%，但需确认模型装得下
  • 何时用：预算硬约束、延迟不敏感的离线任务（如 BAAgent 月报）

5 从技术到商业决策

给 PM 的三个问题：
  1. 你的 Agent 的 $QPS \times T_{avg}$ 乘积决定了最小 GPU 需求——先算这个数
  2. 长上下文占比超过 30%？那 KV Cache 优化比权重量化的优先级更高
  3. "自托管 vs API 调用"的分界点在月成本 ~¥5-10 万——低于这个数通常 API 更省心

API vs 自托管决策树：

  • 月调用量 < 100 万次 → API（OpenAI / Claude / 国产云）通常更便宜，省去运维
  • 月调用量 100-1000 万次 → 边界区，需要精算。自托管 INT4 70B 可能打平
  • 月调用量 > 1000 万次 → 自托管优势明显，尤其是数据隐私要求高的金融场景
  • 特殊需求（数据不出域、定制微调、超低延迟）→ 无论调用量都应自托管
