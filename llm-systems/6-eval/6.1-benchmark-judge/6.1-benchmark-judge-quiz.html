6.1 Benchmark · LLM-as-Judge

如何判断模型和 Agent 好不好用 · 10 题 Quiz

§① 是什么 —— 从考试分数到系统度量
Q1 / 10 · §① 概念辨析
以下关于 Benchmark 的描述，哪项最准确？
ABenchmark 分数高的模型在所有场景下表现都更好
BBenchmark 是标准化考试，但分数不等于你的场景表现（如 MMLU 高分 ≠ 客服机器人好用）
C只需要关注 Chatbot Arena 排名即可选择模型，其他 Benchmark 已经过时
DSWE-bench Verified 是目前最权威的编程能力评测，短期内不会退役
✅ 正确答案：B
这是本章的核心命题之一。Mason AI Lab 明确指出"MMLU 考的是通用知识,你的客服机器人需要的是能根据知识库准确回答"。Benchmark 分数是通用能力的参考指标，不能直接映射到特定场景。→ 回到 §① 复习
Q2 / 10 · §① 应用判断
你负责的 FxAgent（换汇咨询）AI 采纳率达 98-99.75%。以下哪种解读最合理？
A采纳率高 = 模型能力极强，不需要额外评测投入
B应该用 GPQA 推理分数来验证底层模型能力是否足够
C高采纳率可能源于"没得选"效应，需要用户满意度调研+汇率准确性校验来交叉验证
D40万 MAU 足够说明质量，采样偏差可以忽略
✅ 正确答案：C
"用户满意是因为真的好还是因为没得选"正是 PM 需要持续追问的问题。本章强调评测必须结合场景特点——FxAgent 应该用 L1 用户反馈 + L2 A/B Test + L3 汇率实时校验的组合方案。→ 回到 §⑤ 产品连接复习
§② 怎么实现 —— 三层架构与 Judge 偏差
Q3 / 10 · §② 核心概念
Agent 评测三层架构中，L1 规则引擎最适合评测以下哪种维度？
A回复内容的事实准确性和相关性
B尽调报告的分析深度和洞察价值
C输出是否符合 JSON 格式、是否包含禁止词、响应延迟是否超限
D多轮对话中上下文理解的连贯性
✅ 正确答案：C
L1 规则引擎的核心优势是确定性边界检测——格式合规性、安全边界、性能阈值这些可以用代码精确判断的维度。而 A/B/D 属于主观质量评估，应该用 L2 LLM-as-Judge 来处理。→ 回到 §② 复习
Q4 / 10 · §② 方法论
Jason Wei（前 Google Brain）提出 LLM-as-Judge 的核心原则是什么？
AJudge 模型必须比被评测模型强至少一代
B准确性(accuracy) > 一致性(agreement)，优先追求绝对正确
C一致性(agreement) > 准确性(accuracy)，稳定的系统性偏差可以通过校准修正
D必须使用成对比较(pairwise)，单输出评分(single-output)已被淘汰
✅ 正确答案：C
这是本章引用的关键方法论原则。只要 Judge 的评分在不同运行之间高度一致（可复现），即使与人类评分有系统性偏差，也可以通过校准锚点来修正。这大大降低了部署 Judge 的门槛。→ 回到 §② 复习
§③ 为什么 —— 评测的第一性原理
Q5 / 10 · §③ 第一性原理
2026年3月 OpenAI 官宣退役 SWE-bench Verified 的最主要原因是什么？
A测试成本太高，无法维持大规模评测
B数据污染导致模型背题、天花板效应导致区分度丧失、59.4% 测试用例存在缺陷（三因叠加）
CSWE-bench Pro 发布后法律原因强制要求退役旧版
DClaude Opus 4.7 分数太高导致其他厂商集体投诉不公平
✅ 正确答案：B
三大原因是：(1) 数据污染 — 模型预训练见过考题；(2) 天花板效应 — 6个月只涨6%；(3) 测试缺陷 — 近60%问题过宽或过窄。替代方案是 SWE-bench Pro（1865题抗污染企业级）和 SWE-bench-Live（动态更新）。→ 回到 §③ 复习
Q6 / 10 · §③ 深层理解
伯克利 SkyLab 的 Terminator-1 事件暴露了 Agent Benchmark 的什么致命弱点？
AAgent 在多步任务中的记忆管理能力不足
B评测指标可以被 gaming（刷榜），高分不一定代表真实任务解决能力
C开源模型在 Agent 场景中始终不如闭源模型
D终端操作类任务对当前模型来说太难了
✅ 正确答案：B
Terminator-1 在排行榜上高分但实际解决了 0 个任务——极端案例说明"结果导向"评测（SWE-bench 通过单元测试即得分）可能忽略过程质量。这也是 SWE-bench Pro 引入三阶段人工验证流程的原因。→ 回到 §③ 复习
§④ 演进 —— 2024-2026 评测格局
Q7 / 10 · §④ 行业格局
以下哪个 Benchmark 被 Mason AI Lab（2026）认为是最难被 gaming的评测方式？
AMMLU — 57个学科覆盖面广难以针对性优化
BHumanEval — Python函数补全需要真正的编程能力
CChatbot Arena — 动态题库+匿名盲评+集体投票ELO，无法针对人类喜好优化
DGPQA Diamond — 博士级题目难度极高无法刷榜
✅ 正确答案：C
Arena 的四大防 gaming 机制：动态题库（用户实时提问）、匿名盲评（不知道哪个模型）、集体理性（数千票 ELO 收敛）、长尾覆盖（各种语言/领域/风格）。相比之下 MMLU/HumanEval 都是静态题库已被证明可被污染。→ 回到 §④ 复习
Q8 / 10 · §④ 工具链
以下哪个评测框架不是以 LLM-as-Judge 为核心能力的？
ADeepEval — G-Eval + Arena G-Eval + 多轮 Agent 评测
BEvalScope — 100+ 数据集 + Web Dashboard + Agent Evaluation Mode
CLangSmith — Trace + Dataset + Evaluate + Annotation
D以上三个都是围绕 LLM-as-Judge 或 Agent 可观测性的框架
✅ 正确答案：D
这三个都是 2026 年主流评测/可观测框架。DeepEval 专精 LLM-as-Judge SDK；EvalScope 是全栈评测平台（ModelScope 出品），支持 100+ 数据集和 Agent 评测模式；LangSmith 是 LangChain 生态的 Agent 可观测平台。三者定位互补而非竞争。→ 回到 §④ 复习
§⑤ 与产品连接 —— Fitz 的三层评测体系
Q9 / 10 · §⑤ 实战应用
根据出错代价和用户可见度的 ROI 分析，TRSAgent（跨境汇款售后邮件）应该采用什么级别的评测策略？
AL1 用户反馈即可，投入过高 ROI 不划算
BL1+L2+L3 全套 + 金标准回归集 + 持续 CI/CD 回归（出错代价极高+用户直接感知）
CL1 数据脚本验证 + L2 季度专家审核（参考 KBA 的策略）
D只做 LLM-as-Judge 抽检，每月人工审核 20 条即可
✅ 正确答案：B
TRSAgent 处理资金相关售后邮件，出错代价涉及资金损失和合规风险，且客户直接感知。因此需要最高级别的评测投入。你已建立的 206 封金标准测试邮件就是最佳实践——需要扩展并嵌入自动化回归流水线。→ 回到 §⑤ 复习
Q10 / 10 · §⑤ 主线定位
T1 D6.1（Benchmark与LLM-as-Judge）在贯穿主线中回答了什么问题？它如何服务于 T2 A4 Harness 工程？
A回答"信息如何进入模型" → 服务于 T2 A1 Agent Loop 的输入设计
B回答"如何判断模型和Agent好不好用" → 构成 T2 Harness 六组件中"Evaluate 评估反馈闭环"的理论基础
