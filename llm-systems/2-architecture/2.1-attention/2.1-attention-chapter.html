① 是什么：每个 token 动态"问路"

💡 直觉类比

把 Attention 想象成一个跨境支付合同的审查员。

合同里有一句话："付款方须在交割日前三日提交汇款凭证，逾期按日收取 0.05% 违约金"。当审查员读到"逾期"这个词时，他会本能地回头找"交割日"——因为知道"逾期"的含义必须依附于某个时间锚点。

Attention 做的事情完全一样：当前 token 向序列中所有其他 token "发问"，根据相关性动态加权，把最有用的信息拉过来，合成自己的新表示。这种"动态加权"区别于固定权重的卷积——不同语境下，同一个词的关注对象完全不同。

为什么需要 Attention？

在 Transformer 出现之前，RNN 处理序列依靠"接力棒"：每个位置把信息压缩进一个隐向量传给下一位置。问题是长距离依赖会衰减——第 1 个词的信息传到第 100 个词时已经面目全非。

Attention 的根本动机是：让任意两个位置之间直接"通信"，不经过中间节点。距离从 O(n) 降到 O(1)。

三个核心术语

Query Q Key K Value V

用图书馆类比理解三者：

  • Query（查询）：你在图书馆柜台写下的检索需求——"我要找跨境支付监管相关的书"
  • Key（键）：每本书封面上的关键词标签——"监管/合规/支付"
  • Value（值）：书的实际内容，真正会被你带走阅读的信息

Attention 的逻辑：用你的 Query 去比对所有书的 Key，得到"相关度分数"，然后按相关度加权，把各本书的 Value 混合返回给你。

§① 核心结论

Attention 的本质是动态内容寻址：同一个位置在不同上下文中会关注不同的位置，实现了 O(1) 的长距离依赖。三个不同投影（Q/K/V）的分离让"检索"与"存储"解耦，是整个机制能运作的关键设计。

② 怎么实现：Scaled Dot-Product Attention

💡 PM 直觉

整个 Attention 的数学不过是三步走：算相似度 → 归一化 → 加权求和。就像你在评估多个供应商：先给每家打个"契合度分"，然后归一化成"权重比例"，最后把各家的方案按比例混合，得到最终方案。

Step 1：准备三组投影矩阵

输入的 token 嵌入向量 $\mathbf{X} \in \mathbb{R}^{n \times d_{model}}$（n 个 token，每个 $d_{model}$ 维），通过三个可学习的权重矩阵投影：

$$\mathbf{Q} = \mathbf{X} W^Q, \quad \mathbf{K} = \mathbf{X} W^K, \quad \mathbf{V} = \mathbf{X} W^V$$

其中 $W^Q, W^K \in \mathbb{R}^{d_{model} \times d_k}$，$W^V \in \mathbb{R}^{d_{model} \times d_v}$。这三个矩阵是模型训练时学到的，不是固定的——模型会学习用什么"视角"去查询、用什么"标签"去响应、用什么"内容"去传递。

Step 2：计算注意力分数

Q 和 K 的点积衡量"相关程度"，再除以 $\sqrt{d_k}$ 缩放：

$$\text{scores} = \frac{\mathbf{Q}\mathbf{K}^\top}{\sqrt{d_k}} \in \mathbb{R}^{n \times n}$$

得到一个 $n \times n$ 的矩阵，第 $(i, j)$ 个元素代表第 i 个 token 对第 j 个 token 的关注程度（未归一化）。

Step 3：Softmax 归一化

对每行做 Softmax，把原始分数变成概率分布（每行之和为 1）：

$$\mathbf{A} = \text{Softmax}\left(\frac{\mathbf{Q}\mathbf{K}^\top}{\sqrt{d_k}}\right)$$

$\mathbf{A}_{ij}$ 就是"第 i 个 token 给第 j 个 token 分配的注意力权重"。

Step 4：加权聚合 Value

$$\text{Attention}(\mathbf{Q}, \mathbf{K}, \mathbf{V}) = \text{Softmax}\left(\frac{\mathbf{Q}\mathbf{K}^\top}{\sqrt{d_k}}\right)\mathbf{V}$$

用注意力权重矩阵 $\mathbf{A}$ 对 $\mathbf{V}$ 做加权求和：第 i 个位置的输出 = 所有位置的 Value 向量按权重混合的结果。

Scaled Dot-Product Attention 完整流程

一个具体例子：理解注意力矩阵

以序列 "交割 日 逾期" 为例（3个token），注意力矩阵 $\mathbf{A}$ 的第3行代表"逾期"对每个位置的关注度：

交割日逾期
交割0.600.300.10
日0.400.500.10
逾期0.550.350.10

"逾期"这个词把 55% 的注意力分配给"交割"，说明模型学到了它们之间的时间依赖关系。

§② 核心结论

Scaled Dot-Product Attention = QKᵀ 打分 → 除以 √dₖ 稳定 → Softmax 归一化 → 加权 V，输出维度与 V 相同（$n \times d_v$）。整个操作可以用矩阵乘法并行完成，这是 Transformer 训练效率高于 RNN 的关键。

③ 为什么：第一性原理挖掘设计取舍

💡 最关键的问题：为什么要除以 √dₖ？

这是面试必考、理解 Attention 最核心的一个问题。直觉：不除会让 Softmax 饱和，梯度接近于 0。

√dₖ 的第一性原理推导

假设 Q 和 K 的每个元素独立同分布，均值 0，方差 1。则 Q 和 K 的点积 $\mathbf{q} \cdot \mathbf{k} = \sum_{i=1}^{d_k} q_i k_i$：

$$\mathbb{E}[q_i k_i] = 0, \quad \text{Var}[q_i k_i] = 1$$ $$\text{Var}\left[\sum_{i=1}^{d_k} q_i k_i\right] = d_k$$

点积的方差随 $d_k$ 线性增长！当 $d_k = 64$ 时，标准差达到 $\sqrt{64} = 8$，点积取值范围很大。Softmax 面对这么大的输入会怎样？

⚠️ Softmax 饱和问题

Softmax($\mathbf{z}$) 中，若某个 $z_i$ 远大于其他元素（比如 +8 vs 接近 0），softmax 输出几乎是 one-hot（[0,0,...,1,...,0]）。梯度 $\frac{\partial \text{softmax}}{\partial z} \approx 0$，模型无法从这个 token 学到任何东西——即梯度消失。

解决方案：除以 $\sqrt{d_k}$ 把方差归一化回 1：

$$\text{Var}\left[\frac{\mathbf{q} \cdot \mathbf{k}}{\sqrt{d_k}}\right] = \frac{d_k}{d_k} = 1$$

为什么 Q、K、V 要是三个不同的投影？

这是另一个深层设计问题。理论上可以用同一个矩阵 $W$ 同时生成 Q 和 K（相当于 $W^Q = W^K$）。为什么不这么做？

检索与存储的职责分离：

  • Q 代表"我要找什么"（当前 token 的需求），K 代表"我能提供什么标签"（其他 token 的索引描述）
  • V 代表"我真正包含什么内容"（其他 token 要传递的实际语义）
  • 如果 K = V，则"你能被检索到"和"你的内容"完全绑定，无法独立优化。分离后，K 可以专注于"好被发现"，V 可以专注于"内容丰富"

类比：搜索引擎里，网页的SEO关键词（K）和正文内容（V）是两回事——关键词决定你能被搜到，正文决定用户得到什么。

因果掩码（Causal Mask）：为什么生成时不能"偷看未来"

在解码阶段（生成文本），第 $i$ 个 token 不能关注第 $i+1, i+2, ...$ 个 token（因为它们还没生成）。实现方式：在计算 Softmax 之前，将注意力矩阵的上三角部分设为 $-\infty$（经过 Softmax 后变成 0 权重）：

$$\text{Masked-Attention} = \text{Softmax}\left(\frac{\mathbf{Q}\mathbf{K}^\top}{\sqrt{d_k}} + \mathbf{M}\right)\mathbf{V}$$

其中 $\mathbf{M}_{ij} = -\infty$ 当 $j > i$，否则 $0$。

复杂度分析

维度标准 Self-Attention说明
时间复杂度$O(n^2 \cdot d)$QKᵀ 是 n×n 矩阵乘法
空间复杂度$O(n^2)$需存 n×n 注意力矩阵
最大依赖距离$O(1)$任意两 token 直接计算
并行度高矩阵乘法 GPU 友好

$O(n^2)$ 的空间复杂度是长上下文的瓶颈所在（上一章 1.4 解决的正是这个问题），也是 FlashAttention 系列工作的动机。

§③ 核心结论

✦ 除以 √dₖ：防止高维空间中点积方差爆炸导致 Softmax 饱和（梯度消失）
✦ Q/K/V 分离：让检索（K）和内容（V）独立优化，灵活性更高
✦ 因果掩码：训练和推理的一致性保证，阻止模型在训练时"作弊"
✦ $O(n^2)$ 瓶颈：长上下文研究（NSA/FlashAttention）的起点

④ 演进格局：从 MHA 到 MLA 的工程进化

💡 演进主线

Attention 的演进有一条清晰的工程主线：保持或提升模型质量的前提下，减少 KV Cache 内存占用——因为推理时 KV Cache 是显存瓶颈，直接决定能服务多少用户、支持多长上下文。

Multi-Head Attention (MHA) — 原版，2017

《Attention is All You Need》提出。把单个 Attention 拆成 $h$ 个独立的"头"并行计算，每头维度 $d_k = d_{model}/h$，最后拼接：

$$\text{MultiHead}(\mathbf{Q},\mathbf{K},\mathbf{V}) = \text{Concat}(\text{head}_1, ..., \text{head}_h) W^O$$

为什么要多头？每个头可以在不同子空间里学习不同类型的依赖（语法依赖、语义依赖、指代关系等），总体表达能力远超单头。GPT-3 用 96 头，每头 128 维。

MLA 的核心思路（扩展）

MLA（Multi-head Latent Attention，DeepSeek-V2 / arxiv 2405.04434, 2024-05）的核心：不缓存完整的 K, V，而是缓存一个低维压缩向量 $\mathbf{c}$，推理时动态解压。

以 DeepSeek-V2 为例：$d_{model} = 5120$，K 和 V 各 5120 维，缓存 $\mathbf{c}$ 仅 512 维，内存减少 20 倍，KV Cache 总体减少 93.3%，生成速度提升 5.76 倍。

2026 年：Kimi K2、GLM-5 等多家中国头部模型也采用了 MLA 架构，表明这已成为追求推理效率时的行业选择之一。

§④ 核心结论

Attention 变体的演进=减少 KV Cache 内存：MQA/GQA 靠"共享 KV 头"，MLA 靠"压缩潜空间"。FlashAttention 是正交维度的工程优化（IO 效率），不改变算法语义但从 FA-1 到 FA-4 持续提升 GPU 利用率。2026 年行业主流：Dense 模型用 GQA，追求极致推理效率用 MLA。

⑤ 与产品：Attention 在 Fitz 业务场景中的应用

💡 串联思路

每次你用 DDAgent 读一份跨境支付合同、用 KBA 搜索一条合规规则，背后都是 Attention 在做"文本内部的意义路由"。理解 Attention 就是理解 LLM 为什么能读懂长文档中的复杂依赖。

DDAgent：长合同中的关键条款定位

场景：DDAgent 读入一份 80 页的跨境汇款协议，需要定位"什么情况下触发违约金"。

Attention 在这里做的事情：

  • 当模型处理"逾期"这个词时，Attention 会把高权重分配给上文出现的"交割日"、"付款期限"等时间锚点
  • 当处理"违约金"时，会关注"0.05%"、"按日计算"等数值描述
  • 这些跨段落的长距离依赖，是 RNN 做不到但 Transformer 能做到的

产品含义：DDAgent 能准确提取合同条款，本质上依赖于 Attention 跨越段落的动态关注能力。这也是为什么 128K 以上长上下文模型（1.4 章节的主题）对 DDAgent 如此重要。

KBA：知识库问答中的语义匹配

场景：用户在 KBA 中问"新加坡 MPI 牌照对单笔汇款上限是多少"，系统要从知识库中召回正确条目。

Attention 的角色分工：

  • Embedding 层（已在 1.2 章学过）：把问题和文档都变成高维向量
  • Attention 层：在 Encoder 端，让问题里的"MPI牌照""单笔上限"等关键词相互增强，生成更精准的查询表示
  • Cross-Attention（RAG 场景）：在 Decoder 生成答案时，Q 来自问题，K/V 来自检索到的文档，把检索结果和问题需求动态融合

FxAgent：汇率信息的语义感知

FxAgent 处理"某个汇率波动时推送提醒"的任务，需要理解"USD/CNH 的波动"和"提醒时机"之间的条件依赖——这种条件关系在文本中常常是跨句的。

Attention 让模型能捕捉"当……时"和"则……"之间的语义关联，而不依赖句子里的线性位置。

选型决策：什么时候用 GQA vs MLA？

场景推荐理由
自部署推理，显存有限GQA 模型（如 Qwen3-8B）KV Cache 小，可服务更多并发用户
超大规模服务，追求极致吞吐MLA 模型（如 DeepSeek-V3）KV Cache 减少 93%，H100 上 token 成本更低
长文档分析（DDAgent）长上下文模型 + FlashAttentionFA 让 128K+ 上下文计算变得实际可行
RAG / 知识库（KBA）Embedding 模型 + GQA 生成模型检索阶段不需要 MLA，生成阶段 GQA 已足够
§⑤ 核心结论

Attention 对 PM 最重要的产品含义：
✦ 长文档理解能力 = Attention 的跨距离关注（DDAgent 的基础）
✦ RAG 效果 = Cross-Attention 融合检索与生成（KBA 的关键）
✦ 推理成本 = KV Cache 大小（GQA vs MLA 的选型依据）
✦ FlashAttention 是基础设施优化，几乎所有框架默认启用，PM 无需额外配置
