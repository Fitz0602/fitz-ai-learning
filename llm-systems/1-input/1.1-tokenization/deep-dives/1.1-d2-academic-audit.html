§② 怎么实现 — 工业级 BPE 的真实流程

级别审计结论
OK 4 阶段流水线框架正确：NFC 归一化 → 正则预分词 → UTF-8 字节化 → BPE 合并，与所有权威公司的实现一致。cl100k_base 正则代码展示也准确。
OK BPE 训练 6 步算法正确：频次统计 → 选最高频对 → 记录 merge → 替换 → 判断终止。merges.txt 顺序优先级（非贪心最长匹配）的澄清也是正确的。
P2 仅展示 cl100k_base，未提 o200k_base / O200K_PATTERN。LLaMA 4 和 GPT-4o/GPT-5 均使用 O200K_PATTERN 预分词正则（Meta 官方 torchtune 源码确认），这是 2025 年后新模型的标准。章节只展示了 cl100k_base 的正则，建议补充说明 o200k_base 的存在和差异。
✅ §② 评级：基本通过（1 处 P2：预分词正则需补充 o200k_base）

§③ 为什么这样 — BPE 算法的设计哲学

级别审计结论
OK BPE 核心思想阐述准确：从字符级开始反复合并最高频相邻对 → 高频词整token、低频词子词组合、OOV 兜底。与所有权威公司实践一致。
OK 信息论 + Zipf 定律视角正确：幂律分布 → BPE 子词策略是最优压缩，这一理论框架被行业广泛认可。
P1 "BPE 与数字推理因果链"引用 3 篇论文作为支撑，但行业已用行动验证。章节写"2024-2025 多篇论文系统证实"，但更准确的说法是：
  • 行业共识：OpenAI（cl100k_base）、Meta（LLaMA 3/4）、DeepSeek-V3、Qwen3 全部采用 \p{N}{1,3} 数字 3 位切分——4+ 家权威公司行动一致，这才是真正的共识
  • 论文角色：Singh & Strouse 2024 和 Token Awareness 论文是学术解释，非共识来源。行业是先做（GPT-4 用 3 位切分），论文后来解释为什么
建议：把叙事从"论文证明"改为"行业先行动（4+ 家公司一致采用 3 位切分），学术后解释"。
P2 "GPT-2 时代允许任意长度数字合并 → 数学崩溃"表述过于简化。实际上 GPT-2 的 BPE 合并确实会让长数字成为整体 token，但"数学崩溃"的说法缺乏权威公司官方确认。更准确：GPT-2 词表 50K，长数字偶然合并导致表示不稳定，3 位规则是解决方案。
P1 缺失：词表大小是 scaling law 的关键维度。ByteDance ICML 2025（Over-Tokenized Transformer）证明：词表扩大到 2 倍 ≈ 模型参数翻倍的效果，且无额外推理成本。Qwen3.5 官方数据也验证了这一点：词表 150K→250K，编码效率提升 10–60%。这是 §③ "为什么 BPE 有效" 的关键补充——不只是 Zipf 定律，词表大小本身是可 scaling 的维度。
⚠️ §③ 评级：通过+建议（2 处 P1：叙事逻辑修正 + 词表 scaling law；1 处 P2）

§④ 演进与对比 — BPE 的几个变种

级别审计结论
P0 演进表存在事实错误：LLaMA 列在 SentencePiece 下已过时。章节写：
名字使用者核心区别

问题：
  • "LLaMA-1"已过时——LLaMA 3/4 均使用 tiktoken（Byte-level BPE），这是 2024–2025 最重大的 tokenizer 切换之一
  • "GPT-2/3/4"应更新为"GPT-2/3/4/4o/5"，GPT-4o/GPT-5 用 o200k_base
  • 遗漏 LLaMA 4 和 Mistral Tekken
权威来源：Meta 官方 torchtune 代码明确 LLaMA 4 使用 tiktoken + O200K_PATTERN；HuggingFace transformers 文档确认 LLaMA 4 词表 202,048。

P0 缺失：3 年词表 8 倍增长趋势。这是 2023–2026 tokenizer 领域最显著的变化，但章节完全没提：

§⑤ 与产品连接 — 你为什么要懂这些

级别审计结论
OK 成本估算和上下文窗口规划逻辑正确：中文 token 比英文贵 2–3 倍、128K 上下文对中文实际容量更少——这些结论仍然成立。
P1 模型选型建议需更新。章节写"不同模型的 tokenizer 差异很大——同一段文本在 GPT-4o 和 Qwen2 上的 token 数可能差 30%"，但数据已过时：
  • GPT-4o（o200k_base）中文已大幅改善——从 GPT-2 的 53 token 降到 15 token（降 70%）
  • Qwen3.5 词表 250K，官方称编码效率提升 10–60%
  • 2025 年后，头部模型的中文 token 效率差距在缩小，而非扩大
建议：更新为"选模型时优先选大词表模型（200K+），中文场景下 o200k_base / Qwen3.5 / Gemini 3 的 token 效率已接近"。
P1 缺失：词表大小直接影响推理成本（但非线性）。大词表 = embedding 矩阵更大 = 参数更多，但 ByteDance ICML 2025 证明词表扩大的性价比远超模型参数扩大。这是 PM 做模型选型时必须知道的：选大词表模型不会显著增加推理延迟，但能显著降低 token 消耗。
P2 幻觉根因分析缺少 tokenizer 改进方向。章节建议"在 system prompt 里教模型这个词是什么"，但未提 o200k_base / Qwen3.5 大词表已经减少了专有名词被切碎的概率。选大词表模型本身就是解法之一。
⚠️ §⑤ 评级：通过+建议（2 处 P1：模型选型更新 + 词表与推理成本关系；1 处 P2）

🔴 行业共识核心发现（权威公司行动验证）
  1. Byte-level BPE 是绝对主流：5/6 头部公司使用（OpenAI/Meta/DeepSeek/Qwen/Mistral），仅 Google 用 SentencePiece——这是行业共识，不是论文观点

  6. BLT 尚未工业化：2025 开源 + 2026 Fast BLT，但无生产模型采用——研究前沿 ≠ 行业共识
