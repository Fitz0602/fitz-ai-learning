① 是什么

直觉建立 + 产品视角动机 · 术语表

▎前置连接：从位置编码到长度外推
上一章你了解了 RoPE（旋转位置编码）：模型通过旋转 Q/K 向量来注入"相对位置"信息。RoPE 在训练长度内表现优异，但有一个致命短板——超出训练长度，模型的困惑度会爆炸式增长。

LLaMA 2 训练了 4K 上下文，当你喂给它 16K 的文档，模型就像"考场遇到了从未见过的题型"——不是答不好，是根本无从下手。

长上下文扩展（Long Context Extension）就是一组工程方法，让已经训练好的模型能够处理远超训练长度的序列，而无需从头重训。

为什么"超出训练长度"就会崩溃？

回顾 1.3 的知识：RoPE 的每个维度对位置 m 旋转 m × θᵢ 角度。训练时模型只见过 m ∈ [0, Ltrain] 范围内的旋转角度。推理时若位置 m = 50000 而训练只到 4096，低频维度（旋转慢）的旋转角 50000 × θlow 可能还在训练分布内（因为这些维度旋转极慢），但高频维度（旋转快）的 50000 × θhigh 已经远远超出训练时见过的角度范围——模型在这些维度上的注意力权重分配完全失常。

产品经理为什么必须理解长上下文扩展？

你可能会想："这是工程问题，跟我有什么关系？" 恰恰相反——长上下文直接决定了你的 Agent 能处理多长的业务文档。

▎现实场景的"上下文天花板"

关键问题：模型声称的"上下文长度"不等于"有效上下文长度"。一个训练 4K、用 YaRN 外推到 128K 的模型，其中段信息感知能力可能远弱于原生训练 128K 的模型。选错模型 = 你的 Agent 在关键位置"失明"。

▎本节核心 Takeaway
长上下文扩展的本质：解决 RoPE 在超出训练长度时的"分布外（OOD）"问题。不是模型"装不下"更多 token（显存够就行），而是位置编码让模型"看不懂"超出训练范围的位置。

三条路线的分工：路线 A（位置编码缩放）是当前量产方案；路线 B（架构创新）是 2025-2026 的前沿方向；路线 C（输入压缩）是工程兜底方案。它们不是互斥的——Qwen2.5 同时用了路线 A（YaRN）+ 路线 C（RAG 召回），LLaMA 4 同时用了路线 A（大 base RoPE）+ 路线 B（iRoPE）。

② 怎么实现

机制 · 流程图 · 从 PI 到 YaRN 的完整实现链

▎先记住这一句话
所有路线 A 的方法都在回答同一个问题：如何让训练时见过 [0, Ltrain] 位置的模型，在推理时能处理 [0, Lextend] 的位置？
核心手段就是修改 RoPE 的旋转公式，让超出范围的位置"看起来像"训练时见过的位置。

步骤一：Position Interpolation（PI）——最直接的压缩

PI 由 Meta 在 2023 年提出（Chen et al., 2023），思路极其直白：把长序列的位置索引线性压缩到训练范围内。

原始 RoPE 公式中，位置 m 的旋转角为 m × θi。PI 的修改：

原始：旋转角 = m × θᵢ（其中 m ∈ [0, L_extend]）
PI修改：旋转角 = (m / s) × θᵢ（其中 s = L_extend / L_train）

例：L_train=4096，L_extend=131072，则 s = 32
位置 65536 → 被压缩为 65536/32 = 2048，在训练分布 [0,4096] 内 ✓

图 3：PI 均匀压缩 vs NTK-aware 差异化缩放的直觉对比

PI 的问题：所有频率维度被均等压缩 ÷s，相邻位置 m 和 m+1 的旋转角差也被缩小了 s 倍。高频维度本来善于区分近邻位置（旋转角差大），被压缩后这个优势消失——模型的局部信息精度显著下降。实测需要约 1000 step 的微调才能弥补。

步骤二：NTK-aware Scaling——按频率差异化缩放

NTK-aware（Neural Tangent Kernel）不修改旋转角公式本身，而是修改 RoPE 的 base 频率值：

原始 RoPE：θᵢ = base(-2i/d)，其中 base=10000

NTK-aware：把 base 替换为 base' = base × s(d/(d-2))

效果：高频维度（i 小，θ 大）→ 缩放量小，保持局部精度
低频维度（i 大，θ 小）→ 缩放量大，扩展长程感知

类比：就像给望远镜不同焦段的镜片用不同倍率调整——近焦镜（高频）保持精细，远焦镜（低频）做延伸。

步骤三：YaRN——NTK-by-parts + 温度修正

YaRN（Yet another RoPE extensioN）是目前业界最常用的 PI 类方案，由 Peng et al. 2023 提出（Mistral 等使用）。它在 NTK-aware 基础上做了两个改进：

改进①：NTK-by-parts（三段频率策略）

图 4：YaRN 的三段频率策略（NTK-by-parts）

改进②：注意力温度修正（Attention Temperature Scaling）

长上下文时每个 token 能"看到"的候选 token 数量增多，softmax 的注意力分布会趋于平坦（熵增大），导致模型难以聚焦关键信息。YaRN 引入温度参数修正：

温度系数：t = 0.1 × ln(s) + 1（其中 s = L_extend / L_train）

注意力分数：score(q,k) = q·k / (√d × t)

效果：s=32 时 t≈1.35，相当于缩小了 35% 的注意力分布温度， 让模型重新聚焦
▎本节核心 Takeaway
PI → NTK-aware → YaRN 是一条渐进式优化链：
  • PI：简单但损局部精度（均匀压缩 ÷s）
  • NTK-aware：高频保局部精度、低频做长程外推（修 base 值）
  • YaRN：三段策略精细化 + 温度修正防止注意力平坦化
实践中，YaRN 只需约 400 step 微调即可将 4K 模型扩展到 128K，是当前成本最低的量产方案。

③ 为什么

第一性原理 · 设计取舍 · 数学本质

▎核心追问
为什么不直接把 base 设成 10M，训练时就用超大 base？为什么 YaRN 要加温度修正？为什么"高频外推低频内插"是对的而不是反过来？这三个问题的答案，揭示了长上下文扩展的深层逻辑。

第一性原理：高频外推、低频内插 的信号学基础

RoPE 的每个维度对应一个旋转频率 ωi = θi = base(-2i/d)。在训练窗口 Ltrain 内，第 i 维见过的旋转角范围是 [0, Ltrain × ωi]：

图 5：高频外推、低频内插的信号学本质

用数学量化：对 LLaMA base=10000，d=128，训练长 4096：

  • 高频维度 i=0：ω₀ = 1，训练内旋转角范围 [0, 4096]，已经历 652 个完整 2π 周期
  • 低频维度 i=63：ω₆₃ = 10000-126/128 ≈ 0.000146，训练内旋转角范围 [0, 0.6]，不到四分之一圈

为什么 YaRN 要加注意力温度修正？

这涉及 softmax 的熵效应。注意力分数 A = softmax(QKT/√d)：

  • 序列短（如 4K）时，每个 token 的 key 候选有限，softmax 能形成尖峰，注意力集中
  • 序列长（如 128K）时，候选数量增加 32 倍，softmax 结果趋于均匀（熵增大），即使 QK 有相关性，每个 token 的权重也被"稀释"了
▎直觉类比
想象你在 100 人班级里选"最认识的同学"（短上下文），很容易选到 1-2 个。现在换成一万人场合（长上下文），同样的选择标准下，"最认识的人"权重被其他 9900 人稀释，概率排名跌到难以区分——即便你跟他最熟，统计上也看不出来了。

温度修正就是把"投票数量"重新归一化，让熟悉的人重新凸显。

大 base 预训练 vs YaRN 后处理：取舍逻辑

维度YaRN 后处理大 base 预训练
训练成本~400 step 微调（极低）从头或接近从头训练（极高）
效果上限外推+插值有信息损失原生学习长距离关系，效果更优
短上下文精度基本不受影响大 base 降低高频精度（高频维度旋转变慢）
典型代表Mistral 7B, Qwen2.5LLaMA 3 (base=500K), DeepSeek-V3
适用场景已有模型快速扩展，成本敏感新模型立项，追求最高长上下文质量
▎本节核心 Takeaway
高频外推低频内插有坚实的信号学依据：高频维度在训练窗口内见过多个完整周期（外推安全），低频维度连一圈都没走完（外推危险）。

温度修正是对 softmax 熵效应的必要补偿：长序列候选增多会稀释注意力权重，缩小温度让分布重新聚焦。

工程选择：资源充足建新模型 → 用大 base 预训练；已有模型快速扩展 → 用 YaRN（400步）。两者不互斥。

iRoPE：RoPE 与 NoPE 交错的架构创新

LLaMA 4 的 iRoPE 是 2025-2026 最引人注目的长上下文架构创新。其核心设计：

▎iRoPE 设计逻辑
  • 局部注意力层（odd layers）：使用 RoPE，保持短距离精确位置感知
  • 全局注意力层（even layers）：不使用位置编码（NoPE），依靠 Attention 的内容匹配做长程关联，没有位置 OOD 问题
  • 推理时温度缩放：全局层在推理时应用动态温度缩放，增强对超出训练长度的泛化
  • 效果：训练 256K，推理可外推到 10M，在 "needle-in-haystack" 10M 测试中显著优于全 RoPE 架构

NSA：从后处理到架构原生支持

DeepSeek 的 Native Sparse Attention（NSA）代表了另一个方向：不改位置编码，改注意力计算本身。三条并行分支：

分支功能粒度
压缩注意力（Compressed Attn）粗粒度全局模式感知token 块压缩成代表
选择性注意力（Selected Attn）精读高相关块Top-K 块全精度
滑动窗口注意力（Sliding Attn）局部上下文固定窗口

三路结果按门控权重合并，端到端可训练。在 64K 序列下，解码速度提升 11.6 倍，前向传播提升 9 倍。

▎本节核心 Takeaway
长上下文扩展经历了三个阶段：
① 后处理阶段（2023）：PI → NTK → YaRN，成本低效果有上限
② 大 base 预训练阶段（2024）：LLaMA 3 / Qwen2.5 / DeepSeek-V3，原生 128K 成为新基准
③ 架构创新阶段（2025+）：iRoPE（10M）+ NSA，打开百万级上下文窗口

行业共识：短期产品用"大 base + YaRN 辅助"，新建大模型用"大 base 预训练"，前沿探索 iRoPE + NSA。

⑤ 与产品连接

DDAgent / KBA / FxAgent / 跨境支付场景 · 选型速查表

▎PM 的核心提问
产品经理最容易犯的错：把"模型支持 N token"等同于"模型能有效感知 N token"。 这节要建立的心智模型是：名义上下文 ≠ 有效上下文，以及如何为不同业务场景选择合适的长上下文方案。

"名义上下文"与"有效上下文"的鸿沟

2023 年 Liu et al. 的经典论文"Lost in the Middle"揭示了一个残酷事实：即使模型支持 128K 上下文，对文档中间部分的信息感知显著弱于首尾。

图 7：Lost in the Middle —— 模型对文档中段信息感知能力衰减示意

结论：选模型时不能只看名义上下文长度，要用 needle-in-haystack（草垛里找针）测试验证：把关键信息放在文档 30%、60%、80% 位置，看模型是否都能准确提取。

DDAgent：尽调文档的长上下文策略

▎DDAgent 场景分析
DDAgent 核心任务是从 10K-50K 字的尽调问卷中提取关键风险指标。对应 token 量 15K-80K，典型情况是文档结构松散（有效信息分散全文），这正是 "Lost in the Middle" 的高风险场景。

建议策略：
1. 优先选用原生 128K+ 训练模型（如 Qwen2.5-72B-Instruct），而非 YaRN 后处理版
2. 在文档前置插入"摘要索引"引导模型注意力（Prompt 工程）
3. 对超过 60K token 的文档，使用 RAG 分段召回 + 长上下文精读组合（路线 A+C）

KBA：多文档知识库的上下文预算

KBA 的场景是把多段召回内容拼接成上下文喂给模型（RAG+Reader 模式）。典型配置：

组件token 消耗注意事项
System Prompt + 指令~1K-2K放在开头（强感知区）
召回文档段（5-10段）~15K-40K按相关性排序，最相关的放首尾
用户问题 + COT 格式~500放在结尾（强感知区）
模型预留输出空间~2K-4KKBA 最长单次生成约 2K token

关键技巧：把最重要的召回段放在开头或结尾（利用首尾强感知区），而不是中间。这是一个零成本、立即有效的产品优化。

FxAgent：汇率监管文件的快速选型建议

FxAgent 的汇率监管文件比对场景（2 国 × 100 页 ≈ 200K+ token）已超出多数模型的有效感知范围。建议分层策略：

▎FxAgent 实际建议
层一：RAG 召回（路线 C） 先对两国文件分别建立向量索引，用问题驱动召回相关条款（覆盖 80% 的日常查询）

层二：长上下文精读（路线 A） 对于"对比两国 AML 义务差异"这类跨文档推理，用 128K 模型拼接双方核心章节（控制在 60K token 内，放首尾），做深度比对

▎本节核心 Takeaway
三条 PM 实践原则：
1. 名义 ≠ 有效：声称支持 128K 的模型，有效感知可能只到 60K，用 needle-in-haystack 实测
2. 关键信息放首尾：利用"首尾强感知区"，把最重要的上下文放在 prompt 开头或问题紧前方
3. 精确提取用长上下文，快速概览用 RAG：两者不互斥，分层策略才是生产最优解
