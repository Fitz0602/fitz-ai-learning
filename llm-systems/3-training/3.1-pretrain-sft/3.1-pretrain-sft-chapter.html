① 是什么：预训练建世界观，SFT 教行为格式

直觉类比

预训练 = 通读整座图书馆。一个学生花了 10 年读遍图书馆里所有书——科学、历史、小说、法律、菜谱、代码……他学会了语言的规律，掌握了大量世界知识，但你让他"帮我写一封道歉信"，他可能给你续写一篇关于道歉的百科词条。

SFT（监督微调）= 上岗培训。公司给这个百科全书式的人一套"标准问答手册"：用户说 X，你回答 Y。几轮下来，他就知道"当助手该怎么说"了。

预训练：下一个 Token 预测

预训练的核心目标极其简单——预测下一个 Token。给定一段文本的前缀，模型需要猜出下一个最可能的 Token 是什么。

形式化地，给定文本序列 $x_1, x_2, \ldots, x_T$，预训练优化的是：

$$\mathcal{L}_{\text{pretrain}} = -\sum_{t=1}^{T} \log P(x_t \mid x_{这个目标看起来平淡无奇，但当你在 10T+ Tokens 上优化它时，模型被迫学会：

  • 语言结构：语法、词法、标点用法
  • 世界知识：巴黎是法国首都、E=mc²、Python 的 list comprehension
  • 推理能力：如果 A>B 且 B>C，则 A>C
  • 代码逻辑：函数定义、循环、递归

但预训练模型有一个致命问题：它学的是"互联网平均水平的文字接龙"，而不是"对人类有帮助的回答"。你发"帮我翻译这句话"，它可能继续生成"帮我翻译这句话的方法有三种……"——因为它在训练数据里见过太多这种格式。

SFT：从续写到对话

SFT 用指令-回答对（Instruction-Response Pairs）训练模型。每条数据长这样：

用户：帮我解释什么是跨境支付
助手：跨境支付是指不同国家或地区之间的资金转移……

SFT 的损失函数和预训练形式一样（都是下一个 Token 预测），但只在助手回复部分计算 loss——用户指令部分不参与梯度更新。这确保模型学的是"怎么回答"，而不是"怎么提问"。

核心要点

预训练和 SFT 本质上做的是同一件事——预测下一个 Token。区别在于数据：预训练用无标注的互联网语料，SFT 用精心标注的指令-回答对。数据决定了行为，目标函数只是载体。

② 怎么实现：数据配比 + 训练流程 + 高效微调

预训练数据工程：决定模型能力天花板

2024-2026 的行业共识：数据质量 > 数据量。把 100T 垃圾 Tokens 喂进去，不如 10T 干净 Tokens。这就是为什么 Meta、DeepSeek、Qwen 的技术报告都在讲数据工程，而不是模型架构。

直觉类比

预训练数据配比就像食谱配方。同样的食材（算力），同样的锅（架构），谁掌握了最完美的调料比例，谁就能端出米其林级别的菜品。Llama 3.1 的配比是 50% 通用 + 25% 数学 + 17% 代码 + 8% 多语言——这个比例不是拍脑袋定的，而是反复实验的成果。

预训练数据工程五大核心机制

数据退火（Data Annealing）

这是 2024-2025 的主流工艺。训练末段（Cosine LR schedule 的尾巴），学习率降到很低，此时混入更高质量的数据（数学、代码、Wiki）：

  • Cosine 末段自然减速 → 梯度更新幅度小
  • 已学到的 representation 不会被冲散
  • 高质量数据在这个"微调窗口"精细打磨能力
  • Llama 3 明确使用了这个策略

SFT 三种微调方法

方法可训练参数质量硬件需求（70B）成本

LoRA 的核心思想：冻结基础模型，在每个 Transformer 层注入低秩矩阵 $\Delta W = A \times B$，其中 $A \in \mathbb{R}^{d \times r}$, $B \in \mathbb{R}^{r \times d}$, $r \ll d$。可训练参数从 $d^2$ 降到 $2dr$，通常减少 90-99%。

$$h = W_0 x + \Delta W x = W_0 x + BAx$$
常见误区

"有更多数据就更好"是错的。当前瓶颈不是数据量，而是质量 + 去重 + 多样性。SFT 数据也是如此——SmolLM2 的数据构成是 39.4% 数学 + 38.9% 代码 + 17.6% 对话 + 4.1% 指令跟随，数学和代码占比高是因为这些领域有客观正确答案，训练信号清晰。

现代后训练三阶段流水线

2025-2026 行业标准已从两阶段（SFT + RLHF）升级为三阶段：

Stage 1 SFT：指令-回答对 → 学格式与语气
Stage 2 偏好对齐：DPO/RLHF → 学"哪种回答更好"
Stage 3 RLVR：GRPO + 可验证奖励 → 学推理（下一章 3.2 详述）
核心要点

预训练的决定性因素是数据配比（不是模型架构）；SFT 的决定性因素是数据质量（不是微调方法）。LoRA/QLoRA 让中小企业也能做 SFT，但 Base Model 的能力天花板是预训练决定的。

③ 为什么：第一性原理看预训练与 SFT 的设计取舍

直觉类比

为什么不能跳过预训练直接 SFT？就像你不能让一个不识字的人去学写公文。SFT 教的是格式和规范，预训练给的是知识和语言能力。没有预训练打底，SFT 只能教出一个会模仿格式的空壳。

为什么预训练必须是"下一个 Token 预测"？

从信息论角度看，下一个 Token 预测等价于最小化语料的交叉熵：

$$H(P_{\text{data}}, P_\theta) = -\mathbb{E}_{x \sim P_{\text{data}}}[\log P_\theta(x)]$$

当模型完美预测下一个 Token 时，它对数据分布的建模就达到了最优。这个目标的精妙之处在于：

  • 自监督：不需要人工标注，任何文本都是训练数据
  • 可扩展：互联网上有无穷无尽的文本
  • 涌现性：看似简单的目标，在大规模数据上训练后涌现出推理、翻译、编程等能力

为什么 SFT 数据只需几千到几万条？

关键理解：SFT 不是在"教新知识"，而是在解锁已有能力。预训练已经在参数里存了海量知识，SFT 只是告诉模型"当用户这样问时，你应该这样回答"。

形式化地，设预训练模型为 $P_\theta$，SFT 学的是一个格式映射 $f: \text{instruction} \rightarrow \text{format}$，而不是新的知识 $K$。这解释了为什么：

  • InstructGPT 只用了 ~13K 条 SFT 数据就有效果
  • Llama 2 用了 ~27K 条
  • 2025 年行业经验：1-10 万条高质量 SFT 数据足够做通用 Instruct
关键区分

通用 SFT vs 领域 SFT：通用 SFT 教"怎么当助手"，几千到几万条即可；领域 SFT 教"怎么当领域专家"，需要更多领域特定数据。DDAgent 的尽调 SFT 就属于后者——需要注入尽调流程、尽调报告格式等专业知识。

为什么过训练（Overtraining）是新常态？

Chinchilla（DeepMind 2022）给出了理论最优：每 1 个参数配约 20 个 Tokens。但实际趋势完全偏离：

模型参数量训练 TokensToken/Param 比Chinchilla 最优
Llama 3.1 8B8B15T~1875~20
Qwen3-0.6B0.6B36T~60000~20
DeepSeek V4-Flash284B32T~113~20

为什么？因为推理成本按参数量计，训练是一次性投入。一个小模型吃更多 Tokens，推理时又快又便宜，比大模型更划算。这就是"过训练"的经济学逻辑。

为什么 SFT 只在助手回复上计算 Loss？

如果在用户指令上也计算 Loss，模型会学到"用户会说什么"而不是"助手该怎么回答"。这会导致模型在推理时倾向于续写用户输入，而不是生成回答。形式化地：

核心要点

预训练的不可替代性在于知识基础——没有预训练的 SFT 是无本之木；SFT 的高效性在于格式解锁——只需少量数据就能激活预训练中已存储的能力。过训练的经济学逻辑是：训练一次，推理无数次，所以让小模型多学比让大模型少学更划算。

④ 演进格局：2024-2026 数据战争

范式转变：规模战争 → 数据战争

Karpathy 在 2025 年度回顾中明确指出：

"2025 年大语言模型能力的提升，主要源于各实验室对新阶段'存量潜力'的挖掘与释放。模型参数规模未发生显著变化，但强化学习训练的周期大幅延长。"

三个标志性事件宣告了"规模至上"时代终结：

  • Meta 暂停 1T 参数模型研发，转投数据策略（80% 资源）
  • GPT-4.5 参数量与 GPT-4o 相同，优化数据后 MMLU +12.7%
  • Claude 3.5 Sonnet 仅用 Opus 60% 的训练数据和算力，达 92% 性能

数据墙：2027 年的危机

斯坦福 HAI 2026 年白皮书警告：按当前训练消耗速度，互联网高质量英语公共文本将在 2027 Q3 耗尽，多语言文本在 2030 年前也会耗尽。应对方案：

  • 合成数据规模化：Phi-4 约 40% 训练数据为合成，Kimi K2 使用 agentic 合成 pipeline
  • 数据质量提升：FineWeb-Edu、DCLM 等高质量 Common Crawl 子集成为开源标准
  • 难度自适应训练：华为 EDCO（ICML 2026）用推理熵动态编排训练课程

后训练占比上升

Liquid AI 基准测试显示，后训练单独可改进 20-40% 性能——这个量级的提升如果靠预训练扩展，需要数量级更多的算力。Meta Llama 团队的结论更直接：Base Model vs Instruct Model 的差异不是增量改进，而是转型性差异。

核心要点

2024-2026 的核心叙事是从"堆规模"到"榨数据"。预训练阶段，数据配比和质量决定能力天花板；SFT 阶段，少量高质量数据即可解锁预训练能力。后训练（SFT + 偏好对齐 + RLVR）现在占模型可用能力的多数。

⑤ 与产品连接：Fitz 的模型选型决策框架

直觉类比

选模型就像招人：Base Model 是刚毕业的百科全书学霸，什么都知道但不会干活；Instruct Model 是经过入职培训的员工，能听懂指令、规范输出；领域 SFT 后的是资深专家，不仅听话还懂你的业务。

决策 1：Base vs Instruct — 什么时候用哪个？

决策 2：DDAgent 的模型选型

DDAgent（尽调 Agent）的选型逻辑：

  • 预训练数据配比影响推理上限：Llama 3.1 的 25% 数学数据让它在尽调推理任务上有天然优势
  • 领域 SFT 是必须的：通用 Instruct 模型不懂尽调流程、不知道什么是"预填率"
  • Base → 领域 SFT → 领域 RL 是 DDAgent 的实际路径
  • 83% 预填率的背后：预训练给的推理能力 + SFT 给的格式能力 + 领域数据给的专业知识

产品决策陷阱

不要指望通用 Instruct 模型直接做领域专家。FxAgent 换汇场景的错误率从 2% 降到 0.25%，不是因为模型更聪明了，而是因为领域 SFT 注入了汇率规则、合规边界等专业知识。预训练决定推理能力，SFT 决定领域精度——两者缺一不可。

预训练数据配比 → Agent 能力天花板

这是一个经常被忽略但极其重要的洞察：

  • 代码数据占比高 → Tool Use 能力强：Llama 3.1 的 17% 代码数据让它在函数调用、API 交互上更可靠
  • 数学数据占比高 → 推理链更稳定：25% 数学数据让 DDAgent 的多步推理不容易"断链"
  • 多语言占比高 → 跨境场景更友好：Qwen3 的 119 语言让 FxAgent 在多币种场景下游刃有余

选模型时，不要只看 benchmark 分数，还要看它预训练数据的配比——这决定了 Agent 在你业务场景上的能力天花板。

核心要点

产品决策的三层框架：(1) Base vs Instruct 取决于用途；(2) 通用 vs 领域 SFT 取决于业务精度需求；(3) 预训练数据配比决定 Agent 能力天花板。DDAgent/FxAgent/KBAgent 的成功不是靠"更大的模型"，而是靠正确的预训练基础 + 精准的领域 SFT。
