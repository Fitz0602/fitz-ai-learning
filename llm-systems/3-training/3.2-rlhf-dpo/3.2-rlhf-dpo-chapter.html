① 是什么：四种对齐方法的直觉建立

直觉类比 — HR 绩效管理演进史

RLHF = HR 绩效考核系统。HR 设计一套评分标准（奖励模型），让主管给员工打分，然后员工根据分数调整行为（PPO 优化）。优点是科学系统，缺点是评分标准本身可能有偏，且维护成本高。

DPO = 跳过打分，直接排序。与其费劲设计评分标准再打分，不如直接让主管说"A 比 B 好"，然后从这些排序中直接优化员工行为。数学证明：在一定假设下，这两种方式等价。

GRPO = 团队内部竞赛。同一个问题，让一个员工做 G 个版本，组内互相比较，比平均水平好的加分，差的减分。不需要外部评委（无 Critic），组内相对排名就是信号。

RLVR = 用客观标准自动判卷。数学题有标准答案，代码能跑通就能验证——不需要人来评判，规则本身就是奖励信号。

SFT 的局限：只教格式，不教"品味"

上一章我们学了 SFT：用指令-回答对训练模型学会对话格式。但 SFT 有一个根本局限——它只能告诉模型"什么是正确格式"，却无法告诉模型"哪种回答更好"。

核心要点

SFT 解决的是"怎么说"（格式），偏好对齐解决的是"说什么更好"（品味）。四种方法的核心差异在于：奖励信号的来源——RLHF 来自学习的奖励模型，DPO 来自隐含在偏好对中的奖励，GRPO 来自组内相对排名，RLVR 来自可自动验证的规则。2025-2026 的行业趋势清晰：奖励模型正在被淘汰，DPO 和 GRPO 分别统治对话和推理两大场景。

2.2 DPO：直接偏好优化的数学之美

DPO（Rafailov et al., Stanford, 2023.05）的核心洞察：在 Bradley-Terry 偏好模型 + KL 正则化下，RLHF 目标函数存在闭式解。这意味着可以直接在偏好对上优化策略，完全跳过奖励模型训练和 RL 循环。

RLHF 的目标是最大化以下目标：

$$\max_{\pi_\theta} \mathbb{E}_{(x,y_w,y_l)\sim\mathcal{D}} \left[ \log \sigma \left( \beta \log \frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)} - \beta \log \frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)} \right) \right] - \mathbb{E}_x [\text{KL}(\pi_\theta(\cdot|x) \| \pi_{\text{ref}}(\cdot|x))]$$

其中 $y_w$ 是优选回答，$y_l$ 是劣选回答，$\pi_{\text{ref}}$ 是冻结的参考模型（通常是 SFT 后的模型），$\beta$ 是 KL 温度系数。

DPO 的精妙之处：将上述目标对 $\theta$ 求导，可以得到一个仅依赖偏好对的损失函数：

$$\mathcal{L}_{\text{DPO}} = -\mathbb{E}_{(x,y_w,y_l)} \left[ \log \sigma \left( \beta \log \frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)} - \beta \log \frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)} \right) \right]$$
DPO 直觉理解

DPO 告诉模型："对于同一个问题，你应该提高好回答的概率，降低差回答的概率——但偏离原始模型的程度要受控。"它不需要知道"好回答到底有多好"（那是 RM 的事），只需要知道"哪个比哪个好"就足够了。这就是为什么 DPO 只需要偏好对（ranking data），不需要绝对分数（scoring data）。

2.3 GRPO：组内相对策略优化 — DeepSeek-R1 的引擎

GRPO（Group Relative Policy Optimization）由 DeepSeek 于 2024 年 4 月随 DeepSeek-Math 发布，2025 年 1 月随 DeepSeek-R1 爆发。其核心创新：彻底移除了 Critic Model（价值网络）。

GRPO 的工作流程：

  1. 组内采样：对同一 prompt，当前策略采样 G 个输出（通常 G=8~16）
  2. 奖励评估：用奖励函数（可以是规则的、可验证的、或学到的）给每个输出打分
  3. 组内归一化：计算每个输出相对于组内均值的优势 $A_i = (r_i - \bar{r}) / s$
  4. 策略更新：用 clipped PPO-style objective 更新策略，但基线来自组内统计而非 Value Network

核心要点

现代后训练已形成清晰的三层架构：(1) SFT 教格式和基础能力；(2) 偏好对齐（DPO/RLHF）塑造行为品味；(3) RLVR（GRPO+可验证奖励）激发推理能力。GRPO 通过"组内竞争"取代了昂贵的 Critic Model，使得中小团队也能跑起推理级别的 RL 训练。HuggingFace TRL 库已原生支持 GRPOTrainer，成为 2025-2026 工程落地的首选工具。

③ 为什么：第一性原理看对齐方法的设计取舍

直觉类比

为什么不能只用 SFT？就像你给新员工一本《标准问答手册》（SFT），他学会了格式，但你没法把"品味"写进手册里。"什么时候该简洁、什么时候该详细、怎么平衡准确性和可读性"——这种判断力只能通过反馈循环慢慢培养。RLHF/DPO/GRPO 就是构建这个反馈循环的不同工程方案。

为什么 SFT 无法替代偏好对齐？

形式化地看，SFT 最小化的是条件似然：

$$\mathcal{L}_{\text{SFT}} = -\sum_{(x,y)\in\mathcal{D}} \log \pi_\theta(y|x)$$

这会让模型模仿训练数据中的回答分布。问题是：

  • SFT 数据中的"好回答"参差不齐：标注者水平不一，有些回答其实不够好，但 SFT 会一视同仁地模仿
  • SFT 无法表达"相对偏好"：它知道回答 A 可以，回答 B 也可以，但不知道 A 比 B 更好
  • SFT 缺乏探索机制：模型只能在训练数据分布内模仿，无法主动发现更好的回答方式

而偏好对齐的目标函数显式建模了偏好的序关系：

$$P(y_w \succ y_l | x) = \sigma(r(x,y_w) - r(x,y_l))$$

这个序关系才是"品味"的数学本质——不是"这是什么水平的回答"，而是"这个回答比那个好多少"。

为什么 DPO 在数学上等价于 RLHF？

这是一个经常被误解但极其重要的理论结果。在以下两个假设下，DPO 和 RLHF 优化的是同一个目标函数：

  1. 偏好服从 Bradley-Terry 模型：$P(y_w \succ y_l) = \sigma(r^*(y_w) - r^*(y_l))$
  2. 使用 KL 正则化约束策略偏离参考模型的程度

区别纯粹是算法层面的：

  • RLHF：先拟合奖励函数 $r_\phi$，再用 RL 优化策略 → 两步近似
  • DPO：将奖励函数代入目标函数并求闭式解 → 一步到位

所以 DPO 不是"另一种完全不同的方法"，而是 RLHF 的更高效的重参数化。这也是为什么 BearPlex 2026 的结论明确指出："DPO is RL"。

为什么 GRPO 在推理任务上碾压 DPO？

这是 2025 年最重要的实践发现之一。DPO 和 GRPO 的本质差异不在数学目标，而在数据来源：

维度DPOGRPO
数据来源离线固定数据集（偏好对）在线生成（每次采样新输出）
探索能力❌ 无（只能在已有数据上优化）✅ 有（能发现训练数据中没有的策略）
适合任务风格/语气/安全对齐数学/代码/长链推理
失败模式Likelihood Displacement（概率漂移）Cold Start（冷启动问题）

TheoremPath 的分析精准地指出了关键：DPO 是 offline 方法，GRPO/RL 是 online 方法。当模型通过 RL 学会避免一种错误后可能出现新的错误模式——这些新模式不存在于原始 DPO 训练集中，所以 DPO 无法修复；而 GRPO 可以通过在线采样持续发现和修正。

DPO 的特有失败模式：Likelihood Displacement

Razin et al. (2024) 发现了 DPO 的一个隐蔽失败模式：当参考模型 $\pi_{\text{ref}}$ 给某个低质量回答分配了异常高的概率时，DPO 的梯度方向会被扭曲。模型不是在"提升好回答的概率"，而是在"压低参考模型碰巧高估的回答的概率"。这使得 DPO 的实际效果偏离了原本的偏好对齐目标。SimPO 和 IPO 等 DPO 变体部分解决了这个问题。

为什么纯 RL 能涌现推理能力？

DeepSeek-R1-Zero 证明了：即使跳过 SFT 冷启动阶段，仅用 GRPO + 可验证奖励，模型也能自发涌现出推理能力。背后的第一性原理是：

  • 搜索-学习范式：RL 提供了一个搜索空间（所有可能的思维链路径），奖励信号引导搜索方向
  • 长链推理天然有利可图：在数学/编程中，更长的推理链往往对应更高的解题成功率，RL 自然而然地鼓励这种行为
  • 自我进化：模型在训练中逐步发现了"反思""验证""尝试不同解法"等策略，并通过梯度更新固化下来

Nature 论文的评审评价 R1-Zero 为"首个明确的成功案例，将纯强化学习应用于足够好的预训练语言模型"。但这并不意味着 SFT 过时了——R1-Zero 有严重的语言混杂和可读性问题，完整版 R1 仍需 SFT 来修复这些问题。

核心要点

偏好对齐的本质是教会模型"相对好坏判断力"（而非 SFT 的"绝对模仿力"）。DPO 和 RLHF 在数学目标上等价，差异在于工程效率——DPO 更简单稳定，适合 90%+ 的生产场景。GRPO 的突破在于引入在线探索机制，使其在推理任务上超越所有 offline 方法。纯 RL 涌现推理能力的意义不在于"取消 SFT"，而在于证明了奖励信号的形状比监督数据的数量更重要。

④ 演进格局：2022-2026 对齐技术的代际革命

2025 分水岭：奖励模型的消亡

Best AI Web 的总结一针见血："ChatGPT 的技术基石正在从前线退役——不是因为失败了，而是因为更便宜的替代品到来了。"三条独立的技术路线得出了同一个结论：

  • Stanford（DPO）：解析解证明奖励模型可以被消除（2023）
  • DeepSeek（GRPO）：组内统计替代价值网络（2024-2025）
  • Google/Anthropic（RLAIF）：AI 反馈替代人工反馈（2022-2026）

直觉类比

对齐训练和 Fitz 每天做的事高度相关。辅导张帅改掉"方法论缺失"的问题——这就是在对齐一个人的行为品味。EvalAgent 评测 KBAgent 输出好不好——这就是在做自动化偏好评估。TRSAgent 分类准确率 92.2%——背后是对齐训练确保模型"知道什么是对的分类"。

产品陷阱：Reward Hacking 的现实形态

学术文献中的 Reward Hacking（模型钻奖励空子）在实际产品中有各种变形：KBAgent 可能学会了"生成长篇大论看起来很专业的回答"（长度 hack）、TRSAgent 可能学会了"总是预测最常见的那一类"（频率 hack）、FXAgent 可能学会了"永远建议持有不动"（保守 hack）。对抗 Reward Hacking 的最好方法是多元奖励组合（Outcome + Process + Format），以及持续的 holdout set 评测。

核心要点

对齐训练不是学术概念，而是 Fitz 每个 Agent 项目的日常工程。EvalAgent 的架构本质上就是 RLHF 循环的产品化封装，Harness 的 Evaluate 组件是其系统级形态。五个 Agent 项目的对齐需求各异：DDAgent 需要推理级对齐（GRPO 路线），KBAgent/BAAgent 需要品味级对齐（DPO 路线），FXAgent/TRSAgent 需要规则级对齐（Constitutional AI 路线）。理解对齐技术的第一性原理，才能在每个项目中做出正确的工程选择。
