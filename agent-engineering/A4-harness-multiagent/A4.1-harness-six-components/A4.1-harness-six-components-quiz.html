A4.1 Harness 六组件 · 10 题测验

① 是什么 — Harness 的直觉与动机

T2-A4.1-①-1
LangChain 在 TerminalBench 2.0 实验中，将 Agent 准确率从 52.8% 提升至 66.5%，他们做了什么改变？
A. 将 GPT-5.2-Codex 升级为 GPT-5.4
B. 仅优化 Harness（上下文中间件、验证循环、推理预算等），模型不变
C. 增加 Agent 数量，从单 Agent 改为三 Agent 协作
D. 更换基准测试为更简单的数据集
正确答案是 B。LangChain 实验的关键发现是：同一模型（GPT-5.2-Codex），仅通过优化 Harness 组件（上下文中间件、自我验证循环、推理预算分配、循环检测等），准确率提升了 13.7 个百分点，从 Top 30 升至 Top 5。这直接证明了 Harness > 模型升级。→ §①
T2-A4.1-①-2
判断：Harness 是模型内部优化的一部分，比如 RLHF 训练过程。
A. 正确 — Harness 指的是模型训练时的对齐技术
B. 错误 — Harness 是模型和应用之间的工程系统，不涉及模型训练
正确答案是 B。Harness 不是模型的一部分，也不是应用业务逻辑。它是模型和应用之间的"工程化支撑系统"，包含上下文、约束、工具、验证、记忆、反馈六个维度。模型训练（如 RLHF）改变模型权重，Harness 改变模型运行的"环境"。→ §①

② 怎么实现 — 六组件完整解构

T2-A4.1-②-1
Fitz 六组件框架中，"Scaffolding"组件的核心设计原则是什么？
A. 给 Agent 更多选项，让它自主选择最优路径
B. 约束解空间——更少的有效选项 = 更少的错误答案
C. 让 Agent 尽可能长时间运行，减少人为干预
D. 只在 Agent 犯错后才添加约束
正确答案是 B。Scaffolding 的设计原则是"约束解空间而非扩大它"——通过 SOP、检查清单、Linter、类型检查等方式，减少 Agent 可以走的错误路径。这不是限制能力，而是引导到正确路径。→ §②
T2-A4.1-②-2
在行业分解对比中，Fitz 六组件框架与 OpenAI 三层分解的关键差异是什么？
A. Fitz 框架少了 Memory 组件
B. Fitz 把 Goal Boundary 和 Memory 独立为顶层组件，而 OpenAI 归入"架构约束"和"生命周期管理"
C. Fitz 框架不包含 Feedback 组件
D. 两者完全一致，只是命名不同
正确答案是 B。Fitz 六组件框架与行业分解的关键差异：Goal Boundary 和 Memory 被独立为顶层组件。OpenAI 把目标归入"架构约束"、把记忆归入"生命周期管理"，但在 DDAgent 实践中，目标边界和记忆是错误最集中的地方，值得独立关注。→ §②

③ 为什么 — 第一性原理

T2-A4.1-③-1
Harness 之所以比模型更重要，以下哪个不是理由？
A. 模型正在趋同，Harness 是差异化壁垒
B. 模型的推理能力已经达到了理论上限，不可能再提升
C. 错误在多步 Agent 轨迹中会复利，Harness 的 Gate 机制可以打断复利链
D. 模型权重不可控，但 Harness 的每个组件都可以设计和迭代
正确答案是 B。说"模型推理能力已到理论上限"是不对的——模型仍在持续进化。Harness 更重要的三个理由是：①模型趋同而 Harness 分化（差异化壁垒），②错误复利效应（Gate 打断链），③模型不可控但 Harness 可控。理由不是"模型不能再提升"，而是"即便模型提升，Harness 带来的增量可能更大"。→ §③
T2-A4.1-③-2
一个 10 步 Agent 轨迹中，每步错误率 5%。如果插入 Gate 机制能检出 90% 的错误，整体成功率从约 60% 提升到约多少？
A. 约 70%
B. 约 95%
C. 约 80%
D. 约 99%
正确答案是 B。无 Gate：(1-0.05)^10 ≈ 60%。有 Gate：单步失败率从 5% 降至 0.5%（5% × 10% 未检出率），(1-0.005)^10 ≈ 95%。Gate 机制把复利链打断，效果从勉强及格变为高度可靠。→ §③

④ 演进 — 三层跃迁与 2026 成词

T2-A4.1-④-1
Anthropic 的三角色系统（Planner/Generator/Evaluator）中，Evaluator 的核心价值是什么？
A. 替代 Generator 直接编写代码
B. 在模型能力边界附近仍能带来明显增益——即使模型已经很强，独立评估仍能发现 Generator 自检遗漏的问题
C. 降低系统成本，因为不需要人类参与
D. 仅用于训练新的模型权重
正确答案是 B。Anthropic 实验的关键发现：Evaluator 在模型能力边界附近仍能带来明显增益。Generator 容易"自认为完成"（self-check bias），而独立的 Evaluator 用 Playwright 浏览器自动化进行客观评分，能发现自检遗漏。成本虽高 20 倍（$200 vs $9），但输出质量是质的飞跃。→ §④
T2-A4.1-④-2
判断：Prompt Engineering、Context Engineering、Harness Engineering 三者是替代关系，后者淘汰前者。
A. 正确 — Harness Engineering 出现后，不再需要 Prompt 和 Context Engineering
B. 错误 — 三者是层层递进、相互兼容的能力升维，不是替代
正确答案是 B。三者不是替代关系，而是层层递进、相互兼容：Prompt Engineering 是基础（意图对齐），Context Engineering 是进阶（信息供给），Harness Engineering 是全景（系统工程）。即便在 Harness Engineering 时代，写好 Prompt 和管好上下文仍然是基本功。→ §④

⑤ 产品连接 — DDAgent Harness 逐组件审视

T2-A4.1-⑤-1
用 Fitz 六组件审视 DDAgent，哪个组件是当前最大瓶颈？
A. Goal Boundary — Dispatcher 路由经常出错
B. Feedback — Auditor 机制不够完善
C. Memory — 跨会话记忆薄弱，缺少案例库和程序性记忆
D. Tools — 银行工具覆盖不足
正确答案是 C。DDAgent 的 Memory 组件评分仅 2 星（最低），主要问题：跨会话记忆薄弱，缺少历史案例库，没有程序性记忆（相似场景自动复用最优路径）。而 Goal Boundary 和 Feedback 已达到 4 星水平。按"找瓶颈集中火力"原则，Memory 应该优先改进。→ §⑤
T2-A4.1-⑤-2
DDAgent 的 Auditor（只标不改）设计，体现了 Fitz 六组件中哪个组件的什么原则？
A. Scaffolding 的"给 Agent 更多自由度"原则
B. Feedback 的 Gate 机制——质量门槛而非修改工具，让 Agent 自己修正
C. Goal Boundary 的"扩大 Agent 权限"原则
D. Memory 的"持久化状态"原则
正确答案是 B。DDAgent 的 Auditor "只标不改"是 Feedback 组件中 Gate 机制的典型实现：Auditor 是质量门槛（标出问题），而不是修改工具（直接改答案）。这确保了 Agent 被迫自己理解和修正错误，而不是依赖 Auditor 代劳。→ §⑤
