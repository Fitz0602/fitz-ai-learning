① 是什么 — Harness 直觉与核心公式

T2-A4.1-①-1
LangChain 在 TerminalBench 2.0 实验中，将 Agent 准确率从 52.8% 提升至 66.5%（+13.7pp），他们做了什么改变？
A. 将 GPT-5.2-Codex 升级为 GPT-5.4 模型
B. 仅优化 Harness（上下文中间件、验证循环、推理预算等），模型不变
C. 从单 Agent 改为三 Agent 并行协作
D. 更换基准测试为更简单的数据集
正确答案是 B。LangChain 实验的关键发现：同一模型（GPT-5.2-Codex），仅通过优化 Harness 组件（上下文中间件、自我验证循环、推理预算分配、循环检测等），准确率提升 13.7 个百分点（Top 30 → Top 5）。这直接证明了 Harness 工程的价值可以超过模型升级。→ §①
T2-A4.1-①-2
判断：Harness 是模型内部的一部分，比如 RLHF 训练或微调过程。
A. 正确 — Harness 指的是模型训练时的对齐和微调技术
B. 错误 — Harness 是模型和应用之间的工程系统，不涉及模型权重修改
正确答案是 B。Harness 不是模型的一部分，也不是应用业务逻辑。它是模型和应用之间的"缰绳系统"——包含意图边界、上下文记忆、工具环境、编排调度、评估反馈、治理运维六个维度。模型训练（RLHF/微调）改变权重，Harness 改变模型运行的"环境"。→ §①

② 怎么实现 — 六组件详解

T2-A4.1-②-1
Fitz 六组件框架中，Scaffolding（脚手架）的核心设计原则是什么？
A. 给 Agent 更多选项和自由度，让它自主选择最优路径
B. 约束解空间——更少的有效选项 = 更少的错误答案
C. 让 Agent 尽可能长时间运行，减少人为干预
D. 只在 Agent 犯错后才被动添加约束规则
正确答案是 B。Scaffolding 的核心原则是"约束解空间而非扩大它"——通过 SOP、检查清单、Linter、JSON Schema 输出约束等方式，减少 Agent 可以走的错误路径数量。这不是限制能力，而是引导到正确路径上。→ §②
T2-A4.1-②-2
以下哪个 Fitz 组件在 OpenAI / Anthropic / LangChain 的行业实践中没有被独立命名，但 Fitz 认为其值得显式化为顶层组件？
A. Goal Boundary —— 三家都有对应（Prompt Presets / System Prompt / write_todos）
B. Orchestration（多Agent编排）—— 各家以 sub-agent/子代理/task工具形式存在但未独立命名
C. Governance+Ops —— 三家都有 Lifecycle Hooks / PreToolUse Hook / interrupt_on
D. 以上所有组件在各家都有明确对应的独立命名
正确答案是 B。Orchestration 在 OpenAI 中体现为 Sub-agent Coordination、在 Anthropic 中为子代理模式、在 LangChain 中为 task 工具——功能都存在但没有被独立命名为顶层组件。Fitz 基于 DDAgent 的 Supervisor 编排实践经验，认为多 Agent 协作模式值得作为独立的第六维（实际是第四维）组件来关注。→ §②

③ 为什么 — 第一性原理与范式切换

T2-A4.1-③-1
"用好模型 > 提升模型"这个范式切换的前提条件是什么？
A. 模型已经达到物理理论上限，不可能再提升
B. Harness 技术已经完全成熟，不再需要迭代
C. 模型已经达到"可用阈值"，通用能力足够支撑大多数任务场景
D. 模型成本已经降为零，所以不值得再投入优化模型
正确答案是 C。"好用模型 > 提升模型"不是否定模型进步的意义，而是指出一个结构性变化：当模型跨过可用阈值后（2026 年顶级模型已普遍超过此门槛），Harness 工程的边际收益开始超过模型升级。两者是乘法关系 Agent = Model × Harness，不是替代关系。→ §③
T2-A4.1-③-2
一个 10 步 Agent 轨迹中每步错误率 5%。如果插入 Gate 机制能检出 90% 错误，整体成功率从约多少提升到约多少？
A. 从约 60% 提升到约 80%
B. 从约 60% 提升到约 95%
C. 从约 77% 提升到约 90%
D. 从约 50% 提升到约 85%
正确答案是 B。无 Gate 时：$(1-0.05)^{10} \approx 59.9\% \approx 60\%$。有 Gate 后单步失败率从 5% 降至 $5\% \times 10\% = 0.5\%$（未检出率），$(1-0.005)^{10} \approx 95.1\% \approx 95\%$。Gate 机制打断复利链，效果从勉强及格变为高度可靠。→ §③

④ 演进与对比 — 三代演进 + 行业对标

T2-A4.1-④-1
Anthropic 三角色系统（Planner/Generator/Evaluator）的实验数据显示：相比单 Agent 运行，三角色系统的成本和输出质量关系是？
A. 成本降低一半，质量略好
B. 成本基本持平，质量显著提升
C. 成本高约 20 倍，但输出质量是质的飞跃（产生不同类型输出）
D. 成本高约 5 倍，质量提升约 30%
正确答案是 C。Anthropic 数据：单 Agent ~$9 / 20min vs 三角色系统 ~$200 / 6hr，成本差约 22 倍。但关键不在成本倍数，而在于输出质量的差异不是"边际改进"而是"质的飞跃"——系统能产生不同类型的输出。Evaluator（Feedback 组件）在模型能力边界附近仍有效增益。→ §④
T2-A4.1-④-2
判断：Prompt Engineering、Context Engineering、Harness Engineering 三者是替代关系，后者出现后前者就淘汰了。
A. 正确 — Harness Engineering 出现后，Prompt 和 Context Engineering 不再需要
B. 错误 — 三者是层层递进、相互兼容的能力升维，不是替代关系
正确答案是 B。三者不是替代关系而是层层递进的能力升维：Prompt Engineering = 基础层（意图对齐），Context Engineering = 进阶层（信息供给），Harness Engineering = 全景层（系统工程）。即便在 Harness Engineering 时代，写好 Prompt 和管好上下文仍然是基本功。杠杆比从 1x → 10x → 100x 递增。→ §④

⑤ 产品连接 — DDAgent/KBA/EvalAgent 复盘

T2-A4.1-⑤-1
用 Fitz 六组件框架审视 KBA 项目，以下哪项不是 KBA 的主要 Harness 缺位问题？
A. Goal Boundary 缺位——没有"不做什么"的显式约束
B. Feedback Loop 缺位——没有 auditor/Gate 质检机制
C. Tools 组件缺失——没有可用的外部 API 或 MCP 工具
D. Scaffolding 薄弱——缺少 SOP 和检查清单
正确答案是 C。KBA 作为 Knowledge Base Agent，其核心问题不在于缺工具——KB 检索本身是内置能力。真正的缺位在于：（1）Goal Boundary——Agent 经常超出 KB 范围编造答案；（2）Feedback Loop——无质检环节直接输出；（3）Scaffolding——无 SOP 导致结果不一致；（4）Context 工程粗糙。Tools 反而不是主要短板。→ §⑤
T2-A4.1-⑤-2
EvalAgent 作为 Fitz 六组件中哪个组件的产品化实例？它体现了该组件的哪些子能力？（多选特征判断）
A. Orchestration 组件 —— 体现多 Agent 编排和任务分配能力
B. Evaluation + Feedback 组件 —— 体现 LLM-as-Judge、回归测试集、Gate 机制、可观测报告
C. Governance + Ops 组件 —— 体现安全隔离和权限管控能力
D. Context + Memory 组件 —— 体现上下文注入和跨会话记忆能力
正确答案是 B。EvalAgent 本身就是 Fitz 第⑤组件"评估反馈闭环"的独立产品化实例，完整覆盖了 Feedback 的四个子能力：（1）LLM-as-Judge 三路评测（Rule/LLM/Diff）；（2）回归测试集 Golden Set；（3）Gate 机制 Pass/Fail 判定；（4）MD+JSON 可追溯报告。EvalAgent 能从主 Agent 解耦出来成为独立产品，正是 Fitz 正交性设计的优势体现。→ §⑤
