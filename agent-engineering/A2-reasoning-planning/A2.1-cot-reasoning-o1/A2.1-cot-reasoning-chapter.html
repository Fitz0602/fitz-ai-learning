① 是什么：从"脱口而出"到"三思后行"

直觉类比

想象你是一个资深运营专员，面对一个复杂的多币种换汇需求。

以前（传统 LLM），你的反应就像直觉回答——看到问题立刻给出答案，靠的是经验和模式匹配。"用户要换100万USD到HKD？大概778万HKD吧。"

现在（CoT / 推理模型），你会先停下来想一想：当前汇率是多少？用户的换汇额度够不够？有没有更优的路径？分几笔操作手续费更低？想清楚了再给答案。

核心区别只有一句话：不是直接映射 问题→答案，而是生成中间推理轨迹 (reasoning trajectory)，再基于轨迹得出结论。

1.1 Chain-of-Thought 的诞生

2022 年，Google Research 的 Wei 等人在 NeurIPS 发表了里程碑论文 "Chain-of-Thought Prompting Elicits Reasoning in Large Language Models"。

他们的发现简单到令人震惊：

# 传统 prompt —— 模型直接输出答案（经常错） Q: Roger 有 5 个网球，他又买了 2 罐网球，每罐有 3 个。 他现在总共有几个球？ A: 11 # CoT prompt —— 只加了 6 个字，模型开始展示思考过程 Q: 同上的问题 A: Let's think step by step. Roger 最开始有 5 个球。# step 1 2 罐 × 3 个/罐 = 6 个球。# step 2 5 + 6 = 11 个球。# step 3 所以答案是 11。# final answer
关键洞察

"Let's think step by step" 这 6 个字，触发了大语言模型潜藏的推理能力。

在 GSM8K 数学基准测试上，PaLM 540B 从 17.9% 跃升到 55.7%。不是换了模型，不是加了数据，只是改了 prompt。这说明：推理能力一直存在于模型中，只是需要一个触发器把它释放出来。

1.2 系统1 vs 系统2：Kahneman 的完美类比

Daniel Kahneman 在《思考，快与慢》中提出的双系统理论，是理解 CoT 和推理模型的最佳心智模型：

系统1 快思考系统2 慢推理
对应技术 Prompt Engineering / Few-shot Chain-of-Thought / o1 / DeepSeek-R1
计算时机 Pre-training 阶段（训练时"想好"） Test-time 推理阶段（运行时"再想"）
响应方式 直觉式、一步到位 分步展开、自我验证
典型场景 "今天天气怎么样？" / "翻译这句话" "证明这个数学定理" / "排查这个 Bug"
成本特征 固定 token 数、低延迟 可变 token 数、延迟随难度波动
类比 FXAgent 查汇率（1轮够用） DDAgent 做尽调（需要多步推理+工具调用）

1.3 CoT 不是魔法——它的工作原理

CoT 有效的根本原因可以用一个公式概括：

$$ P(\text{Answer} \mid Q) = \sum_{\tau \in \mathcal{T}} P(\tau \mid Q) \cdot P(\text{Answer} \mid \tau, Q) $$

其中 $\tau$ 是一条推理轨迹 (reasoning trajectory)。传统模型直接估计 $P(\text{Answer} \mid Q)$，而 CoT 把它分解为两步：

第一步：生成轨迹 $P(\tau \mid Q)$

模型先生成一系列中间推理步骤。这些步骤就像解题时的草稿纸——不需要给用户看，但它们为最终答案提供了计算路径。

第二步：基于轨迹推导答案 $P(\text{Answer} \mid \tau, Q)$

有了完整的推理链路后，得出最终答案的概率大幅提高——因为模型不需要"跳过"中间逻辑，而是沿着已验证的路径一步步到达结论。

第一性原理

CoT 的本质是将一个高难度的条件概率分解为多个低难度的条件概率的乘积。这和人类解决复杂数学题时的策略完全一致：不会试图一步心算出答案，而是先在草稿纸上列出中间步骤。

2.2 G1: CoT Prompting——零样本触发

最简单的 CoT 形式，只需要在问题后面追加一句 magic words：

# Zero-shot CoT：最简形式 prompt = """ {question} Let's think step by step. """ # Few-shot CoT：提供示例引导（效果更好但需要人工编写示例） prompt = """ Q: 小明有 3 个苹果，小红比小明多 2 个，小刚是小红的 2 倍。小刚有几个？ A: 小明 3 个。小红 3+2=5 个。小刚 5×2=10 个。答案是 10。 Q: {question} A: Let's think step by step. """
G1 的局限
  • 依赖模型规模：CoT 效果只在 ~100B 参数以上的模型上显著（小模型反而可能被干扰）
  • 不可控的轨迹质量：模型生成的推理步骤可能是错的，但没有反馈机制纠正
  • 固定计算预算：不管问题多难，都只能跑一轮推理

2.3 G2: CoT Training——从提示到训练

当 Prompt Engineering 到达天花板后，研究者转向让模型学会生成长推理链：

RLVR: Reinforcement Learning with Verifiable Rewards

核心思想：对于数学/代码等有确定正确答案的任务，不需要人工标注推理过程——只需验证最终答案是否正确即可作为奖励信号。

流程：

  1. 对每个问题采样多条不同的推理轨迹 $\{\tau_1, \tau_2, ..., \tau_k\}$
  2. 验证每条轨迹的最终答案：$r_i = \mathbb{1}[\text{answer}(\tau_i) = \text{ground\_truth}]$
  3. 用 PPO 或类似算法优化策略，使高质量轨迹获得更高概率

关键优势：无需人工标注 CoT 数据，模型自己探索出有效的推理策略。

GRPO: Group Relative Policy Optimization（DeepSeek R1 核心创新）

PPO 的问题：需要一个独立的 critic 网络来估计状态价值 $V(s)$，训练复杂且不稳定。

GRPO 的解法：放弃 critic 网络，改为组内相对比较：

$$ A_i = \frac{r_i - \text{mean}(\{r_1,...,r_G\})}{\text{std}(\{r_1,...,r_G\})} $$

对同一个问题采样 $G$ 条轨迹（一个 group），用组内奖励的归一化值作为优势函数。$G$ 条轨迹互相作为 baseline——不需要额外的 value model。

效果：训练效率提升显著，且避免了 PPO 的不稳定性。这是 R1-Zero 能"纯 RL 无 SFT 就涌现推理能力"的关键技术支撑。

2.4 G3: o1/R1 系统机制——推理模型架构

2024 年 9 月，OpenAI 发布 o1 系列，首次将 CoT 从"技巧"升级为"系统级基础设施"：

o1 架构的两个核心设计：

Reasoning Tokens（推理 Token）

这是 o1 最重要的设计决策之一。模型在回答之前会先生成一串不可见的 reasoning tokens——这些就是它的"思维过程"。用户看不到，API 也返回不了（除非使用特殊参数）。

为什么要隐藏？因为推理过程包含大量试错、回溯、甚至错误假设。暴露出来会：(1) 干扰用户体验；(2) 被竞争对手用于蒸馏攻击；（3）产生安全风险（推理过程中可能出现有害思路）。

Test-time Compute Scaling

o1 的推理时间（和 token 消耗）不是固定的——它根据问题难度动态调整。简单问题可能只用几百个 reasoning tokens，复杂问题可能用数万个。

这引入了一条全新的 scaling law：除了预训练计算 (pre-training compute) 和后训练计算 (post-training compute)，还有第三条——推理时计算 (test-time compute)。

2.6 DeepSeek R1：开源推理模型的里程碑

2025 年 1 月，DeepSeek 发布 R1（arXiv:2501.12948），成为开源社区最重要的推理模型：

R1-Zero：纯 RL 的"Aha Moment"

DeepSeek 做了一个大胆实验：完全不使用 SFT（监督微调），仅用纯 RL 训练基础模型。

令人惊讶的事情发生了——模型自发涌现出了推理能力：

  • 训练早期：模型输出的都是乱码和无意义文本
  • 训练中期：突然出现长文本的思维链结构（Aha Moment!）
  • 训练后期：CoT 质量和任务表现持续提升

这意味着什么？推理能力不需要被"教"——只要奖励信号设计得当（GRPO），模型会自己学会如何思考。

R1：Cold-start SFT 解决工程问题

R1-Zero 虽然证明了原理，但有严重的工程缺陷：

  • 语言混合：推理过程中混杂中英文，可读性差
  • 格式混乱：缺乏统一的 CoT 格式
  • 重复冗余：大量无意义的循环推理

R1 的解决方案：先用数千条长 CoT 样本做 cold-start SFT（这些样本来自 R1-Zero 的少量高质量输出 + 人工筛选），然后再用 GRPO 做 RL 训练。最终效果：保持推理能力的同时，解决了可读性和格式问题。

R1 的三个关键数字
  1. 671B 参数（MoE，37B 激活）——与 o1 同级规模的推理能力
  2. MIT 开源——完全开放权重，任何人都可以部署和研究
  3. 蒸馏到 7B：GSM8K +27%——用 R1 生成的 80 万条 CoT 微调小模型，性能大幅提升，实现近 100x 的模型压缩

2.7 Test-time Compute Scaling：第三条规模定律

Snell et al. (2024) 在论文 "Scaling LLM test-time compute optimally can be more effective than scaling model parameters" 中提出了一个颠覆性的观点：

核心发现：在固定的推理计算预算下，合理分配计算资源（如搜索更多推理路径或延长单条推理链），其效果可能超过直接增大模型参数。

具体数据来自 EuroMLSys 2026：

配置模型大小推理预算GSM8K 准确率内存占用
基线 14B 参数 标准推理（~500 tok） 82% ~28GB
TTC 加持 4B 参数 2000 token 推理预算 90% ~8GB

结论：4B 小模型 + 充足的 test-time compute，不仅准确率超过 14B 大模型，还节省了 71% 内存。这对边缘设备和成本敏感场景意义重大。

NeurIPS 2025 Kinetics 的冷水

不过，Kinetics (NeurIPS 2025) 也指出：小模型 + TTC 的效果在某些场景下被高估了。原因在于注意力机制的二次复杂度——当推理序列变长时，注意力的计算成本成为主导因素，而非参数本身的 FLOPs。稀疏注意力 (sparse attention) 是解决这个问题的关键方向。

③ 为什么：第一性原理——计算如何转化为智能

3.1 推理规模定律的形式化

为什么更多的推理时计算能换来更好的答案？让我们回到第一性原理。

对于一个给定的问题 $Q$ 和答案空间 $\mathcal{A}$，最优推理策略可以形式化为：

$$ \pi^*(Q) = \arg\max_{\tau \in \mathcal{T}(Q)} \left[ \log P(A^* \mid \tau, Q) + \log P(\tau \mid Q) \right] $$

其中：

  • $\mathcal{T}(Q)$ 是所有可能的推理轨迹空间
  • $P(\tau \mid Q)$ 是模型生成某条轨迹的概率
  • $P(A^* \mid \tau, Q)$ 是该轨迹导出正确答案的条件概率
直觉解释

这个公式的含义是：最好的推理策略是在"轨迹的可能性"和"轨迹的正确性"之间找到平衡。

  • 短轨迹：$P(\tau|Q)$ 高（容易生成），但 $P(A^*|\tau,Q)$ 可能低（容易跳过关键步骤）
  • 长轨迹：$P(\tau|Q)$ 低（需要更多计算），但 $P(A^*|\tau,Q)$ 高（覆盖更多推理细节）

Test-time compute 的作用就是允许模型探索更大的 $\mathcal{T}(Q)$ 子集，找到更优的 $\tau^*$。

3.2 为什么 RL 能教会模型"如何思考"？

这可能是本章最深的问题：为什么强化学习能让模型学会推理，而不是仅仅记住答案？

关键洞察：RL 优化的是策略，而非记忆

在 SFT（监督微调）中，模型学习的是 $P(\tau \mid Q_{train})$——即模仿训练集中已有的推理轨迹。如果训练集里的 CoT 示例质量不高或覆盖不足，模型就学不到好的推理策略。

而在 RL（特别是 RLVR/GRPO）中，模型学习的是一个探索策略：

  1. 对每个问题，模型自主采样多条不同的推理路径
  2. 每条路径根据最终答案的正确性获得奖励
  3. 策略更新使高奖励路径的概率增加，低奖励路径的概率降低
  4. 经过大量迭代，模型学会了哪些推理模式倾向于产生正确答案

关键区别：SFT 教模型"别人是怎么想的"，RL 让模型自己发现"怎么想才能做对"。这就是 R1-Zero 能纯 RL 涌现推理能力的根本原因。

3.3 计算换智能的边界在哪里？

Test-time compute 不是无限的——存在明显的边际递减效应和新的失效模式：

2026 年最新发现（重要！）

发现 1：位置偏差放大效应（arXiv:2605.06672）

更长的推理轨迹会放大位置偏差 (Position Bias)——模型倾向于过度关注推理链末尾的信息，忽略前面的关键步骤。在 12/13 种实验配置中，推理链长度与位置偏差呈正相关。这意味着：想得越久，不一定越好，还可能在系统性偏见的道路上越走越远。


发现 2：停止条件的困境（arXiv:2605.06690）

新框架提出用 epistemic state graph（认识状态图） 来决定何时停止推理。核心指标是 order-gap——衡量当前认知状态的"不确定性"是否已经足够收敛。基于置信度的 Early-Stopping 在 MathQA 上将得分从 81 提升到 83.6（ICLR 2026 Self-Calibration）。


核心结论：不是"想越久越好"，而是需要更智能的停止点。理想的推理模型应该像一个经验丰富的人——知道什么时候已经"想够了"，而不是无限纠结下去。

第一性原理总结

推理规模定律的核心命题：智能不完全等于参数规模。在特定条件下，将计算从"训练时"重新分配到"推理时"，可以获得更高的智能产出。

但这有三个前提：

  1. 模型必须具备基本的推理能力（太小的不行——G1 的局限性）
  2. 奖励信号必须能区分好坏答案（数学/代码天然适合，主观评价难）
  3. 必须有合理的停止条件（否则边际递减甚至负收益）

这三条也是当前研究的活跃方向。

4.3 2026 年最新研究方向

方向 1：推理过程的可控性

当前推理模型的最大问题是不可控——你无法指定模型应该用什么策略、走哪条路径、花多少计算量。2026 年的研究聚焦于：

  • Structured Reasoning：约束推理过程遵循特定的逻辑结构（如先定义变量、再列方程、最后求解）
  • Budget-aware Inference：在给定的 token 预算内最大化推理质量
  • Verifiable CoT：每一步都可以被自动验证（数学/代码领域已有进展）
方向 2：推理效率优化
  • Speculative Decoding for Reasoning：用小模型草拟推理链，大模型验证修正
  • Sparse Attention in Long CoT：解决长推理序列的注意力瓶颈（Kinetics 2025 关键建议）
  • Early Exiting：基于置信度提前终止推理（Self-Calibration, ICLR 2026）
方向 3：推理安全与对齐
  • Reasoning-level Safety：不仅检查输出，还要监控推理过程中的危险思维路径
  • Distillation Defense：防止通过 reasoning tokens 蒸馏出模型能力（o1 隐藏 reasoning tokens 的动机之一）

⑤ 与产品连接：推理能力在实际 Agent 中的应用

理解了 CoT 和推理模型的抽象机制后，关键问题是：这些能力如何在 Fitz 的 Agent 产品中落地？

5.1 什么时候该用推理模型？

不是所有任务都需要推理模型。决策矩阵如下：

任务特征推荐方案理由
简单查询 / 翻译 / 摘要 标准模型（GPT-4o / Claude Sonnet） 推理模型浪费 token，延迟更高
多步规划 / 复杂分析 推理模型（o1 / R1 / o4-mini） 长 CoT 能显著减少错误
代码生成 / 数学计算 / Debug 推理模型（优先 o3 / R1） 这些领域有确定性奖励信号，RL 训练效果最好
高频低延迟场景 标准模型 + 缓存 FXAgent 这种 40 万月活的场景，延迟敏感

5.2 DDAgent 尽调场景中的推理应用

DDAgent（企业尽调）是最需要推理能力的场景之一——它需要在多个信息源之间做交叉验证、识别矛盾、推断隐含风险：

# DDAgent 使用推理模型的伪代码 def ddagent_reasoning_analysis(company_data: dict) -> dict: """ 用推理模型做深度尽调分析 场景：发现财务报表和工商信息之间的不一致， 需要模型进行多步推理来推断真实情况。 """ analysis_prompt = f""" 你是企业尽职调查分析师。以下是一家公司的多源数据，请仔细分析： ## 工商信息 注册资本: {company_data['registered_capital']} 成立日期: {company_data['founded_date']} 法人: {company_data['legal_representative']} ## 财务报表（最近3年） {json.dumps(company_data['financials'], ensure_ascii=False, indent=2)} ## 法律风险扫描 {json.dumps(company_data['legal_risks'], ensure_ascii=False, indent=2)} 请逐一分析： 1. 财务数据与注册资本是否匹配？有无异常？ 2. 法律案件是否暗示经营风险？ 3. 综合评估这家公司的信用等级（A/B/C/D）及理由。 """ # 使用推理模型（如 o4-mini 或 DeepSeek-R1-Distill-Qwen-7B） response = call_reasoning_model( model="deepseek-reasoner", # 或 "o4-mini" prompt=analysis_prompt, max_tokens=16000 # 推理模型需要更大的 token 预算 ) return { "credit_grade": parse_credit_grade(response), "risk_flags": extract_risk_flags(response), "reasoning_trace": response.reasoning_tokens # 用于调试和审计 }
为什么 DDAgent 需要推理模型？

考虑这个真实案例：一家公司注册资本 100 万，但财务报表显示年收入 5 亿。标准模型可能会分别报告这两个数字，但推理模型会注意到这个比例异常（500 倍！），主动去查找是否有未披露的关联交易或虚增收入嫌疑。

这就是推理模型的价值：不只是报告数据，而是发现数据之间的关系和异常。

5.3 成本权衡：推理模型的经济账

推理模型不是免费的午餐。以 o4-mini 为例（2025 定价）：

场景标准模型成本推理模型成本倍数值得吗？
FXAgent 单次汇率查询 ~$0.001 ~$0.008-0.02 8-20x ❌ 不值得（简单任务）
BAAgent 月度经营分析 ~$0.15 ~$0.40-0.80 3-5x ⚠️ 看场景（有时值得）
DDAgent 企业尽调 ~$0.50 ~$1.20-2.00 2-4x ✅ 值得（减少误判损失更大）
代码审查 / 安全扫描 ~$0.30 ~$0.60-1.50 2-5x ✅ 值得（漏检代价高昂）
成本优化策略
  1. 分级路由：简单问题走标准模型，复杂问题升级到推理模型（可用轻量分类器做前置路由）
  2. 蒸馏模型替代：用 R1 蒸馏出的 7B/14B 模型处理大部分场景，仅在极端困难问题上调用原生 R1/o1
  3. 缓存常见问题：尽调中的标准化分析模板可以缓存推理结果
  4. 控制推理预算：设置 max_completion_tokens 上限，防止简单问题也跑满推理 budget

5.4 KBA（Knowledge Base Agent）场景

KBA 场景涉及知识库问答，推理模型在这里的价值体现在：

推理模型在 KBA 中的三种用法
  1. Query 理解：将模糊的自然语言问题转化为精确的结构化查询。例如"去年我们亏了多少"→ 解析为"查询 2025 财年净利润字段，关注亏损金额"
  2. 多文档综合推理：当答案分散在多个 KB 文档中时，推理模型能更好地做信息聚合和矛盾消解
  3. 答案置信度校准：推理模型的长 CoT 过程天然包含了"我对这个答案有多大把握"的信息——可用于决定是否需要人工审核

本章核心收获
  1. CoT 本质：将 $P(A|Q)$ 分解为 $P(\tau|Q) \cdot P(A|\tau,Q)$——用中间推理轨迹降低问题的条件复杂度
  2. 系统1 vs 系统2：Prompt Engineering 是快思考，CoT/推理模型是慢思考——两者互补而非替代
  3. 三代技术：G1 Prompting（6个字触发）→ G2 Training（RLVR/GRPO 教会思考）→ G3 System（o1/R1 的 reasoning tokens + TTC scaling）
  4. 三条 Scaling Laws：Pre-train / Post-train / Test-time compute——第三条是 2024-25 年最大的范式转移
  5. 不是想越久越好：位置偏差放大 + 停止条件困境——2026 年的核心课题是"智能停止"而非"无限推理"
  6. 产品落地的关键是分级路由：简单问题用标准模型省成本，复杂问题用推理模型保质量
