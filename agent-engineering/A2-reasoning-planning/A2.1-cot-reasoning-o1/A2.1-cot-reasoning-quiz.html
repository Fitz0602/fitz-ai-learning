Q1 §① 是什么

1. Wei et al. 2022 年的 CoT 论文中，触发模型推理能力的关键短语是？

  1. APlease explain your reasoning in detail.
  2. BLet's think step by step.
  3. CShow me your thought process before answering.
  4. DBreak down the problem into smaller parts first.
解析

正确答案是 B。"Let's think step by step" 是 CoT 论文中的 magic words。这个短语在 GSM8K 上让 PaLM 540B 从 17.9% 跃升到 55.7%。其他选项虽然语义相近，但不是论文中验证过的触发词。

Q2 §① 是什么

2. 在系统1 vs 系统2 的类比中，以下哪项不正确地描述了 CoT / 推理模型的特征？

  1. A系统2（推理模型）的计算量根据问题难度动态变化
  2. B系统1 对应 Prompt Engineering，系统2 对应 Chain-of-Thought
  3. C系统1 的延迟总是比系统2 更高（因为需要更多训练）
  4. DFXAgent 查汇率适合用系统1，DDAgent 做尽调更适合用系统2
解析

正确答案是 C。C 是错误的描述——系统1（快思考）的特征恰恰是低延迟、固定成本，而系统2（慢推理/CoT）因为要生成中间推理链，延迟更高且随问题难度波动。选项 C 把两者的延迟关系说反了。

Q3 §② 怎么实现

3. GRPO（Group Relative Policy Optimization）相比 PPO 的核心改进是什么？

  1. A不需要独立的 critic/value 网络，用组内采样互相作为 baseline
  2. B引入了更强的奖励模型来评估推理质量
  3. C使用更大的学习率和更少的训练步数加速收敛
  4. D将 reward 从标量改为向量以支持多目标优化
解析

正确答案是 A。GRPO 的核心创新就是放弃 critic 网络，改为对同一个问题采样 G 条轨迹，用组内奖励归一化值作为优势函数：$A_i = \frac{r_i - \text{mean}(\{r_1,...,r_G\})}{\text{std}(\{r_1,...,r_G\})}$。这解决了 PPO 需要 value model 的复杂性和不稳定性问题，也是 R1-Zero 能纯 RL 涌现推理能力的关键。

Q4 §② 怎么实现

4. 关于 OpenAI o1 系列的 Reasoning Tokens，以下说法正确的是？

  1. AReasoning Tokens 默认对用户可见，用于展示思考过程
  2. BReasoning Tokens 和 Completion Tokens 数量比例固定为 1:1
  3. CReasoning Tokens 只在数学任务中生成，代码任务不会使用
  4. DReasoning Tokens 默认隐藏，长度根据问题难度动态调整
解析

正确答案是 D。o1 的 reasoning tokens 有两个关键特征：(1)默认隐藏（用户不可见）；(2)长度可变（简单问题几百 token，复杂问题数万 token）。隐藏的原因包括：避免干扰用户体验、防止蒸馏攻击、规避安全风险。A 错在"默认可见"，B 错在"固定比例"，C 错在适用范围。

Q5 §③ 为什么

5. EuroMLSys 2026 的实验数据表明：一个 4B 小模型配合 2000 token 推理预算，GSM8K 达到 90%，超过 14B 大模型的 82%。这说明了什么？

  1. A大模型已经过时，应该全面转向小模型+长推理
  2. BTest-time Compute Scaling 可以在某些条件下替代参数规模扩展
  3. CGSM8K 数据集太简单，不能反映真实推理能力
  4. D4B 模型的预训练数据质量远高于 14B 模型
解析

正确答案是 B。这是 Test-time Compute Scaling 核心命题的直接证据：合理分配推理时计算可以超越增大模型参数的效果。同时该配置还节省了 71% 内存（8GB vs ~28GB）。但注意 A 过于绝对化——这只是在特定条件（有确定性答案的数学题）下的结论；C 和 D 与实验结论无关。

Q6 §③ 为什么

6. 根据 2026 年最新研究，以下关于"更长推理轨迹"的说法，哪个是正确的？

  1. A推理越长效果越好，不存在边际递减
  2. B位置偏差与推理链长度无关
  3. C更长的推理会放大位置偏差（Position Bias），需要智能停止机制
  4. D2026 年研究证明推理模型已完美解决所有停止条件问题
解析

正确答案是 C。arXiv:2605.06672 的研究发现：12/13 种配置下，推理链长度与位置偏差呈正相关——模型倾向于过度关注推理末尾信息而忽略前面的关键步骤。arXiv:2605.06690 提出了 epistemic state graph + order-gap 指标的智能停止方案，ICLR 2026 Self-Calibration 用 Early-Stopping 将 MathQA 从 81 提升到 83.6。所以核心结论是：不是想越久越好，而是需要更智能的停止点。A、B、D 都是错误的。

Q7 §④ 演进

7. DeepSeek R1-Zero 的 "Aha Moment" 指的是什么现象？

  1. A模型突然学会了写代码而无需任何代码训练数据
  2. B纯 RL 训练过程中，模型自发涌现出长文本思维链结构
  3. C模型在某一天突然达到了 AGI 水平
  4. DSFT 阶段一次性加载了大量 CoT 数据后的性能跃升
解析

正确答案是 B。R1-Zero 使用纯 RL（无 SFT）训练基础模型。训练早期输出乱码，中期突然自发出现长文本的 CoT 结构（即 Aha Moment），后期 CoT 质量和表现持续提升。这说明推理能力不需要被"教"，只要奖励信号设计得当（GRPO），模型会自己学会如何思考。A 和 C 都是对 Aha Moment 的夸大或误读，D 错在 R1-Zero 没有 SFT。

Q8 §④ 演进

8. DeepSeek R1（完整版）在 R1-Zero 基础上增加了 Cold-start SFT，主要解决哪些工程问题？

  1. A推理准确率不足，无法达到 SOTA 性能
  2. B推理速度太慢，无法满足生产环境需求
  3. C模型参数量过大，无法有效部署
  4. D语言混杂（中英混合）、格式混乱、重复冗余等可读性问题
解析

正确答案是 D。R1-Zero 虽然证明了"纯 RL 可涌现推理能力"的原理，但有严重的工程缺陷：(1) 语言混合——推理过程混杂中英文；(2) 格式混乱——缺乏统一 CoT 格式；(3) 重复冗余——大量无意义循环推理。Cold-start SFT 用数千条高质量长 CoT 样本（来自 R1-Zero 少量输出 + 人工筛选）做微调，再接 GRPO RL，最终保持了推理能力同时修复了这些问题。A 错在 R1-Zero 准确率已经很高，B/C 不是 Cold-start SFT 要解决的。

Q9 §⑤ 与产品连接

9. Fitz 的 Agent 产品矩阵中，以下场景最不适合使用推理模型（如 o1/R1）的是？

  1. AFXAgent：用户查询 USD/CNH 实时汇率（月活 40 万，延迟敏感）
  2. BDDAgent：企业尽调中的多源数据交叉验证和风险推断
  3. CBAAgent：月度经营分析报告中的异常指标归因
  4. D代码审查 Agent：识别潜在安全漏洞和逻辑错误
解析

正确答案是 A。FXAgent 查询汇率的特征：(1) 任务极简（查表返回数值即可）；(2) 高频高并发（40万月活）；(3) 延迟敏感（用户期望毫秒级响应）。这三条都指向标准模型而非推理模型——推理模型不仅浪费 token（成本 8-20x），还会增加不必要的延迟。B（尽调交叉验证）、C（异常归因分析）、D（安全漏洞检测）都是典型的"需要多步推理"的场景，适合使用推理模型。

Q10 §⑤ 与产品连接

10. 关于推理模型在生产环境的成本优化策略，以下组合中最合理的是？

  1. A全量切换到推理模型 + 不设 max_completion_tokens 让模型自由发挥
  2. B只使用蒸馏后的小模型（如 7B）完全不用原生推理模型
  3. C问题难度分类器前置路由 + 蒸馏模型处理大部分 + 复杂问题升级原生模型 + 设定 token 预算上限
  4. D缓存所有推理结果避免重复调用（不管问题是否相似）
解析

正确答案是 C。这是一个分层优化策略的组合拳：

(1) 前置路由：先判断是否真的需要推理模型（避免对简单问题浪费资源）
(2) 蒸馏优先：用 R1-Distill-7B/14B 处理大多数中等难度场景
(3) 按需升级：仅在极端困难问题上调用原生 R1/o1
(4) 预算控制：设置 max_completion_tokens 上限防止失控

A 全量切换太贵且没必要；B 放弃了原生模型处理极端难题的能力；D 不切实际——每个用户的尽调问题都不同，缓存命中率低。
